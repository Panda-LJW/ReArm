# 现有前端接口规范

后端按这份格式提供数据，前端显示生产进度、机械臂姿态、零件与配方文档、训练和生产记录。本文描述当前控制台的 **v1 实现**，不包含设备层任务书提出的 v2 改造。

当前控制台连接的是浏览器内 `createMockConsole`，没有接入真实主机，也不读取地址栏 `backend` 参数。下面明确区分已实现的数据格式和可复用的网络适配器，不能把本文当成真机已经接通的证明。

## 1. 对接入口与交付文件

| 项目 | 当前内容 |
|---|---|
| 页面入口 | `rearm/ui/static/modules/console/main.js` |
| 数据入口 | `source.subscribe(message => store.dispatch(message))` |
| 指令入口 | `source.send(cmd, args)`，返回 Promise |
| 协议版本 | `v: 1`；握手还要求 `proto: 1` |
| 指令数量 | 9 个，见第 4 节 |
| 消息数量 | 15 种，见第 5 节；另有本地连接通知 `link` |
| 消息与指令样例 | [消息样例.json](接口样例/控制台-v1/消息样例.json) |
| 完整交互样例 | [完整交互.json](接口样例/控制台-v1/完整交互.json)，含全部遥测和请求应答 |
| 核对依据 | [核对基线.json](接口样例/控制台-v1/核对基线.json)，记录源码哈希和验证结果 |

样例来自当前模拟主机实际输出，包含完整生产、新增零件、新增配方、重训、拒绝请求与急停重置五个场景。每个场景独立启动，ID 和序号不能跨场景拼接。样例中的坐标、偏差、夹持力和训练数值均为演示数据。

## 2. 数据怎么进出

### 2.1 数据源接口

| 方法 | 返回 | 现有行为 |
|---|---|---|
| `start()` | 无 | 启动；重复调用不重复启动 |
| `stop()` | 无 | 停止推送并取消未完成流程；重新启动不续跑 |
| `subscribe(callback)` | 取消订阅函数 | 回调收到原始消息；若已有消息，立即回放最近一条 |
| `send(cmd, args = {})` | `Promise<Reply>` | 发指令；参数放报文顶层 |
| `advance(ms)` | 无 | 仅模拟主机的离线时间推进方法 |
| `commands` | 数组 | 仅模拟主机的请求记录，成功和拒绝都保留 |

应先订阅，再 `start()`，才能收到完整开机消息。后订阅只回放最近一条，不是完整状态快照。页面使用 `store + send`，不直接访问电机、相机或网络。

### 2.2 网络适配器的现有约定

仓库已有 `datasource/host-source.js`，但当前控制台没有加载它。它支持以下传输规则；主机端对应路由仍需提供，控制台入口也需接线。

| 方向 | 方式 | 格式 |
|---|---|---|
| 主机 → 前端 | WebSocket 文本消息 | 每条一个 JSON 对象 |
| 前端 → 主机 | `POST /api/v1/command` | `Content-Type: application/json` |
| 主机 → 前端应答 | HTTP JSON 响应体 | 第 3.3 节的 Reply |

WebSocket 路径由 `createHostSource({url})` 的完整地址决定，没有固定 `/events` 路径。适配器把同一主机、端口转换为 HTTP 命令地址：`ws` 对应 `http`，`wss` 对应 `https`，路径固定 `/api/v1/command`，清掉原查询串和片段。

例如 `ws://example.invalid:9000/telemetry` 对应 `http://example.invalid:9000/api/v1/command`。该域名只作示例。给当前控制台加 `?backend=...` 不会启用这个适配器。

适配器默认 3,000 ms 没收到任何消息就报离线，1,000 ms 后重连。任何收到的载荷都会刷新超时计时，但只有能解析为对象且 `v===1` 的消息会转交 store。普通遥测可维持连接；`heartbeat` 可维持传输，但当前控制台 store 不保存它。

跨源部署时，主机须为实际页面 Origin 提供 `POST/OPTIONS` 与 `Content-Type` 的 CORS 响应，并单独检查 WebSocket Origin。现有适配器没有配置授权头、跨源凭据或请求超时；这些不是已实现能力。

## 3. 公共字段

### 3.1 主机推送

以下字段出现在第 5 节全部 15 种消息的顶层。

| 字段 | 类型 | 约定 |
|---|---|---|
| `v` | integer | 固定为 1 |
| `type` | string | 消息名称 |
| `seq` | integer | 同一主机实例所有推送共用递增序号，从 1 开始 |
| `t` | integer | Unix 毫秒；不是秒，也不是任务用时 |

消息内数字必须有限，不发送 NaN、Infinity 或数字字符串。除明确允许 null 或省略的字段外，按本文完整提供。现有 store 只做部分校验，不会替发送方检查所有字段。

推送序号与请求序号是两套计数，互不对应。当前协议没有 `session_id`；主机重启、时钟倒退及历史恢复尚无完整处理，不能假设重连就能恢复任务。

### 3.2 前端请求

| 字段 | 类型 | 约定 |
|---|---|---|
| `v` | integer | 1 |
| `cmd` | string | 第 4 节指令名 |
| `seq` | integer | 当前数据源的请求递增序号 |
| `t` | integer | Unix 毫秒；网络适配器用浏览器时间，模拟用模拟时钟 |
| 业务参数 | 按指令 | 放顶层，不包在 `args` 或 `data` 中 |

```json
{"v":1,"cmd":"run_start","seq":1,"t":1794715200000,"recipe_id":"plate-tube"}
```

没有 `request_id` 或幂等键。后端不能把请求 `seq` 当成跨页面、跨重连的唯一操作 ID。

### 3.3 指令应答

| 字段 | 类型 | 约定 |
|---|---|---|
| `v` | integer | 1 |
| `seq` | integer | 原样返回请求序号 |
| `ok` | boolean | 本次指令是否接受或处理成功，不代表生产完成 |
| `code` | string | 成功为 `ok`；拒绝见第 8 节 |
| `msg` | string | 可直接给用户看的原因；成功可为空字符串 |

```json
{"v":1,"seq":1,"ok":true,"code":"ok","msg":""}
```

```json
{"v":1,"seq":2,"ok":false,"code":"busy","msg":"正在执行其他操作"}
```

应答没有 `t`、`run_id` 或 `train_id`，业务 ID 从后续推送取得。模拟实现可能先同步推送状态，再兑现 `send()` 的 Promise；不要要求“收到应答之前不能收到事件”。读取文档也通过推送返回文档，HTTP 应答本身不放文档。

## 4. 前端发出的 9 个指令

| `cmd` | 业务参数 | 接受条件 | 接受后的消息 |
|---|---|---|---|
| `run_start` | `recipe_id:string` | 待命、无训练或拍照、配方存在 | `run_state(selfcheck)`，随后生产消息 |
| `estop` | 无 | 数据源在线且尚未急停 | `run_state(estop)`、`joint_state` |
| `reset_estop` | 无 | 在线 | 急停时转 idle；否则成功且无变化 |
| `reset_demo` | 无 | 在线，包括急停中 | `demo_reset`、idle、折叠姿态 |
| `library_get` | 无 | 在线、未急停 | `library` 全量列表 |
| `part_get` | `id:string` | 在线、未急停、零件存在 | `part_doc` |
| `recipe_get` | `id:string` | 在线、未急停、配方存在 | `recipe_doc` |
| `part_capture` | 无 | 待命、无训练或拍照 | 1,500 ms 后 `part_candidate` |
| `train_start` | `target:"part"或"recipe"`、`draft:object` | 待命、无训练或拍照、草稿有效 | `train_progress`，完成后更新文档与库 |

读库和读文档可在生产或训练中调用。急停时只接受 `reset_estop`、`reset_demo`，包括再次 `estop` 在内的其他命令都返回 `estop`。当前没有逐轴运动、单独开合夹爪、暂停、取消训练、删除文档或修改设置的指令。

### 4.1 新增零件的 draft

| 字段 | 类型 | 约束 |
|---|---|---|
| `name`、`code` | string | 去空格后非空；code 在零件库内唯一 |
| `outline` | `number[2][]` | 至少 3 个二维点，每点两个有限数字 |
| `size_mm` | `number[3]` | 长、宽、高，全部大于 0 |

```json
{"v":1,"cmd":"train_start","seq":3,"t":1794715201500,"target":"part","draft":{"name":"环形垫片","code":"P005","outline":[[0,7],[7,0],[21,0],[28,7],[28,21],[21,28],[7,28],[0,21]],"size_mm":[28,28,6]}}
```

零件候选由 `part_capture` 产生；前端允许编辑名称、编号再提交。模拟实现把新零件建成 ring，夹持力填 12 N、开口 full，独立几何模型未由此接口上传。

### 4.2 新增配方的 draft

| 字段 | 类型 | 约束 |
|---|---|---|
| `name`、`code` | string | 去空格后非空；code 在配方库内唯一 |
| `fixture_id` | string | 当前模拟仅接受 `disc-fixture` |
| `steps` | object[] | 非空有序数组 |
| `steps[].part_id` | string | 已存在的零件 ID |
| `steps[].target_id` | string | 当前仅接受 `post` |

```json
{"v":1,"cmd":"train_start","seq":4,"t":1794715200000,"target":"recipe","draft":{"name":"薄片单件配方","code":"R002","fixture_id":"disc-fixture","steps":[{"part_id":"plate","target_id":"post"}]}}
```

步骤顺序取数组顺序，完成时由主机补 `index` 和 `target_name`。新增配方不调用 `part_capture`。

### 4.3 重新训练

```json
{"v":1,"cmd":"train_start","seq":5,"t":1794715200000,"target":"part","draft":{"id":"plate"}}
```

`target:"recipe"` 同样可重训已有配方。保留原 ID、名称、编号、几何与配方内容，替换训练记录，`version + 1`，更新 `collected_at`；不增加库条目。不存在的 `draft.id` 返回 `invalid_args`。该指令不是修改文档内容的接口，附加字段不会用于改名或改配方。

## 5. 主机推送的 15 种消息

下表及后续字段表均继承第 3.1 节的公共头。字段放顶层，不另包 `payload`。

| `type` | 必填业务字段 | 用途 |
|---|---|---|
| `hello` | proto、host_version、arm、threshold_mm、camera、sim | 连接信息 |
| `joint_state` | mode、q、dq、current、temp、valid、gripper_mm、gripper_valid、pass、node、settled、fault | 机械臂状态 |
| `run_state` | run_id、recipe_id、phase、step_index、step_total、part_id | 当前生产工序 |
| `selfcheck_item` | run_id、item、ok | 一项自检结果 |
| `recognition` | run_id、image、targets | 识别结果 |
| `step_state` | run_id、index、action、part_id、status、force_n；pick 另含 angle_deg | 一次抓取或放置 |
| `inspect_result` | run_id、ok、deviation_mm | 本套装配检查 |
| `run_done` | run_id、recipe_id、ok、deviation_mm、duration_ms | 生产记账，尚未收回 |
| `library` | parts、recipes | 库摘要全量替换 |
| `part_doc` | 第 6.2 节零件文档字段 | 零件详情 |
| `recipe_doc` | 第 6.3 节配方文档字段 | 配方详情 |
| `part_candidate` | outline、size_mm、name、code | 待确认的零件 |
| `train_progress` | train_id、target、round、deviation_mm、grasp_ok、images、elapsed_ms | 训练进度 |
| `train_done` | train_id、doc_id | 训练完成且已入库 |
| `demo_reset` | 无额外字段 | 清空本次生产和训练记录 |

### 5.1 hello

| 字段 | 类型 | 当前值或含义 |
|---|---|---|
| `proto` | integer | 1，前端可操作判定会检查它 |
| `host_version` | string | 当前模拟为 `console-v1` |
| `arm` | object | `{model:"reBot Arm B601-DM",joints:6}` |
| `threshold_mm` | number | 当前 1，供设置与训练曲线显示 |
| `camera` | object | `{url:null,format:null,width:640,height:480}` |
| `sim` | boolean | 模拟为 true；会影响重置按钮行为 |

此处不要求旧训练页面的 `laser_ttl_ms`、`node_timeout_ms`。设置页只展示参数，不能修改。`camera.url` 当前没有被生产页用来播放视频，详见第 10 节。

### 5.2 joint_state

| 字段 | 类型 | 单位、范围与空值 |
|---|---|---|
| `mode` | string | idle / practice / estop；兼容字段，不表示具体工序 |
| `q` | `(number|null)[6]` | J1 至 J6，rad，URDF 零位与正方向 |
| `dq` | `(number|null)[6]` | 同顺序，rad/s |
| `current` | `(number|null)[6]` | 电流 A，不是力矩 |
| `temp` | `(number|null)[6]` | 温度 ℃ |
| `valid` | `boolean[6]` | 按轴表示有效；v1 没有每种测量各自的有效位 |
| `gripper_mm` | number 或 null | 两指内侧间距，当前配置 0–110 mm |
| `gripper_valid` | boolean | 夹爪数据有效性 |
| `pass`、`node` | null | 控制台不使用的旧训练字段 |
| `settled` | boolean | 是否已停止变化；模拟以各轴速度接近 0 判断 |
| `fault` | null | 当前模拟没有具体故障对象定义 |

当前每 50 ms 推送一次，即 20 Hz。运动、训练和拍照期间 mode=practice；急停时为 estop，其他为 idle。页面工序必须用 run_state，训练活动用 train_progress。

缺测保留 null，并将该轴 valid=false；不能填 0。该约定继承旧 v1，当前模拟没有产生缺测样例。夹爪不放进 q 的第 7 项。前端内部 Three.js 使用 m，线上 q 用 rad、开口用 mm，不要传角度制或将开口换成 m。

| 轴 | 前端显示范围 rad |
|---|---|
| J1 | -2.8 至 2.8 |
| J2 | -3.14 至 0.3 |
| J3 | -3.14 至 0.05 |
| J4 | -1.87 至 1.95 |
| J5 | -1.57 至 1.57 |
| J6 | -3.14 至 3.14 |

与真机后端 PANEL_LIMITS 一致（2026-11-15）。这是当前前端模型配置，不是已确认的真机保护范围。hello 不会自动替换限位、夹爪范围、TCP 或相机安装位置；当前也没有 device_profile 消息。

### 5.3 生产状态与自检

`run_id`、`recipe_id` 为字符串或 null；`part_id` 无当前零件时为 null。`step_index` 抓放阶段从 1 开始，普通非抓放阶段为 0；done、to_fold 当前取总步数。`step_total` 为配方步骤数。

| `phase` | 页面文字 | 含义 |
|---|---|---|
| idle | 待命 | 可以开始下一套，另需在线且不在训练 |
| selfcheck | 自检中 | 检查设备 |
| to_observe | 就绪 | 正在到观察位，尚不能再次开始 |
| recognize | 识别中 | 识别工装与零件 |
| pick | 抓取中 | 当前步骤抓取 |
| place | 放置中 | 当前步骤放置 |
| inspect | 检查中 | 检查整套 |
| done | 完成 | 结果已产生，尚未收回 |
| to_fold | 完成 | 收回中 |
| estop | 急停 | 当前操作中断 |

正常收回后的 idle 仍带本轮 run_id、recipe_id 和 step_total，step_index 为 0；开机、解除急停、重置时的 idle 则是空任务，两个 ID 为 null、步数为 0。不要仅凭 run_id 非空认定仍在生产。

自检 `item` 只有 `comm、j1、j2、j3、j4、j5、j6、gripper、depth_camera` 九项。ok 为 boolean，未收到某项表示尚未检查。现有模拟全部通过，没有失败原因字段或自动中止的完整失败协议。

### 5.4 识别与抓放

`recognition.image` 为 `{width:number,height:number}`。每个 targets 元素如下：

| 字段 | 类型 | 约定 |
|---|---|---|
| `id` | string | 当前模拟工装、柱、零件的 ID |
| `kind` | string | fixture / post / part |
| `name` | string | 显示名称 |
| `confidence` | number | 0–1，页面直接乘 100 显示百分比 |
| `box_px` | `number[4]` | `[左上x,左上y,宽,高]`，像素，左上原点、右/下为正 |
| `angle_deg` | number 或 null | 当前零件为 0°，工装与柱为 null |

当前未定义任意识别角的零方向、旋转正方向及周期，不能将演示中的 0° 当作已完成实机约定。当前零件 id 与 part_id 相同，尚未区分同类零件的多个实物实例。

`step_state.index` 对应 run_state.step_index；action 为 pick/place；status 为 started/done。force_n 为每指法向夹持力，单位 N；pick 带 angle_deg，place 不带。识别角与抓取角只作本轮显示，不进入文档或生产历史。

先发匹配的 run_state，再发 step_state，后者的 t/seq 必须更新；否则 store 会忽略它。run_id、action、index、part_id 都必须匹配。done 事件驱动本地场景把零件标成已夹起或已放下，place done 发生在最后撤离动作结束前约 500 ms，不能理解为整个工序已完全停止。

### 5.5 检查结果与完成

inspect_result.ok、run_done.ok 均为 boolean；deviation_mm 必须是有限非负数。页面根据 ok 决定“到位”或“偏差 x.x mm”，不是自行比较阈值。当前 v1 只有一个偏差值，尚未定义真实装配的测量方法或 unknown 结果。

run_done.duration_ms 是从开始到检查完成的毫秒数，不包含收回。先 inspect_result，再 run_state(done)，再 run_done；后面还必须发送 to_fold 和 idle。

生产页完成套数等于按 run_id 去重后的 run_done 数量，**包含 ok=false 的已完成套**。一次通过率为 ok=true 套数 / 完成套数，零套为 null；最近偏差取最后 20 条。检查前急停没有 run_done，不增加完成套数。

### 5.6 训练进度与结束

| 字段 | 类型 | 约定 |
|---|---|---|
| `train_id` | string | 本次训练 ID |
| `target` | string | part / recipe |
| `round` | integer | 开始立即发 0；正式轮次从 1 开始 |
| `deviation_mm` | number 或 null | round=0 为 null；正式轮次当前为有限非负数 |
| `grasp_ok` | boolean 或 null | round=0 为 null；正式轮次表示试抓结果 |
| `images` | integer | 累计图像数，非本轮增量 |
| `elapsed_ms` | integer | 累计训练用时，非本轮增量 |

第 0 轮用于声明训练已开始，不进入轮次曲线。训练不发送新的 run_state(training)，页面由活动训练覆盖显示“训练中”。train_done 必须匹配当前活动 train_id；只发完成消息而没有进度，当前 store 不会建立训练记录。

完成顺序固定为 `part_doc 或 recipe_doc → library → train_done`。train_done.doc_id 指向已更新文档；target 和轮次等信息由同 train_id 的进度补齐。

当前代码每 1,200 ms 播放一轮，共 8 轮、9,600 ms；但上报的训练用时为每轮 300,000 ms，共 2,400,000 ms（40 分钟），图像数 4,800。这是演示时钟，不是实测耗时。旧接口附录 C 尚未说明此处时间缩放，本文与样例按当前代码记录。后端返回真实数据时，不要从 t 的差值替换 elapsed_ms，也不要照抄这些模拟数值。

## 6. 零件库、配方与训练记录

### 6.1 library 摘要

parts、recipes 都是数组，每次完整替换对应列表，不是增量更新。

| 字段 | 类型 | 适用 |
|---|---|---|
| `id`、`name`、`code` | string | 两类文档 |
| `collected_at` | integer | Unix 毫秒 |
| `version` | integer | 正整数 |
| `shape` | string | 零件；现有 ring / tube / box |
| `size_mm` | `number[3]` | 零件；长、宽、高 |

现有零件为 plate（薄片）、tube（空心圆柱）、sleeve（短轴套）、block（方垫块）；配方 plate-tube，工装 disc-fixture，定位柱 post。这些是当前演示 ID，不能据此自动映射另一套后端的零件编号。

### 6.2 part_doc

除摘要字段外，零件文档含以下字段。文档字段直接放消息顶层。

| 字段 | 类型 | 含义 |
|---|---|---|
| `photo_url` | string 或 null | 浏览器可访问的图片地址；当前为 null |
| `outline` | `number[2][]` | 零件局部二维轮廓，当前按 mm 生成；前端按范围归一显示，不是图像像素框 |
| `force_n` | number | 每指法向夹持力 N |
| `force_basis` | object | 夹持力估算依据，见下段 |
| `opening` | string | 当前仅 full，对应“全开” |
| `training` | object | 第 6.4 节的训练记录 |

force_basis 含 estimated_mass_kg（kg）、material（字符串）、friction_coefficient、safety_factor、gravity_m_s2（m/s²）、fingers（整数）。当前公式：`force_n = estimated_mass_kg × gravity_m_s2 × safety_factor ÷ friction_coefficient ÷ fingers`。这是演示估算，没有将 N 换成电机力矩的接口。

### 6.3 recipe_doc

含 id、name、code、collected_at、version，以及下表字段。

| 字段 | 类型 | 含义 |
|---|---|---|
| `fixture_id`、`fixture_name` | string | 工装 ID 和显示名称 |
| `steps` | object[] | 按装配顺序排列 |
| `steps[].index` | integer | 从 1 开始 |
| `steps[].part_id` | string | 零件文档 ID |
| `steps[].target_id`、`target_name` | string | 放置位置 ID 与名称，当前为 post、定位柱 |
| `part_ids` | string[] | 去重的关联零件 ID，供页面打开文档 |
| `training` | object | 第 6.4 节的训练记录 |

文档不含运动轨迹、逐轴命令或抓取角。当前接口也没有上传 3D 模型、工装坐标或抓放路径的字段。

### 6.4 training 记录

| 字段 | 类型 | 含义 |
|---|---|---|
| `threshold_mm` | number | 曲线阈值，当前 1 |
| `rounds` | object[] | round、deviation_mm、grasp_ok、images、elapsed_ms，语义同训练进度，包含正式轮次 |
| `grasp_records` | object[] | 每项 `{round:integer,ok:boolean}` |
| `images`、`elapsed_ms` | integer | 最终累计图像数与毫秒数 |
| `success_rate` | number | 试抓成功轮数 / 总轮数，0–1；不同于生产一次通过率 |
| `recorded_at` | integer | Unix 毫秒 |
| `video_url` | string，可省略 | 有实际可访问录像时提供；当前页面已支持，预置文档未提供 |

图片和视频必须是浏览器可访问地址，不能是主机磁盘路径。训练录像用原生 video 播放，默认静音；地址加载失败会移除入口。当前没有媒体上传接口。

## 7. 消息顺序

### 7.1 开机

```text
本地 link(online=true)
→ hello
→ library
→ run_state(idle)
→ joint_state，此后 20 Hz
```

library 变化后生产页会请求当前选择的 recipe_get；文档打开时发 part_get 或 recipe_get。不能只发 hello 就期待页面已有配方。

### 7.2 两件装配

| 相对开始时间 | 发送内容 |
|---|---|
| 0 ms | run_state(selfcheck) |
| 300 至 2,700 ms | 九条 selfcheck_item，间隔 300 ms |
| 3,000 ms | run_state(to_observe) |
| 7,000 ms；7,200 ms | run_state(recognize)；recognition |
| 9,500 ms | 第 1 步 pick 状态和 started |
| 14,000 ms；14,500 ms | pick done；第 1 步 place 状态和 started |
| 19,000 ms；19,500 ms | place done；第 2 步 pick 状态和 started |
| 24,000 ms；24,500 ms | pick done；第 2 步 place 状态和 started |
| 29,000 ms；29,500 ms | place done；run_state(inspect) |
| 32,500 ms | inspect_result → run_state(done) → run_done |
| 34,000 ms；38,000 ms | run_state(to_fold)；run_state(idle) |

这些时间来自当前模拟实现，真实主机应按实际动作结果发送，而非按表定时宣告完成。run_done 之后开始按钮仍不可用，直到 idle。

### 7.3 新增零件与配方

零件：`part_capture → part_candidate → 用户确认名称编号 → train_start → train_progress(round=0…8) → part_doc → library → train_done`。

配方：用户选工装、零件和顺序后，直接 `train_start`；后续同上，完成文档为 recipe_doc。入库由训练完成自动发生，没有单独 save 指令。

### 7.4 急停、解除和重置

模拟 estop 取消生产、拍照、训练队列，冻结当前姿态与开口，发 run_state(estop)。reset_estop 解除并进入空任务 idle，保留姿态、计数与已完成记录，原流程不续跑。

reset_demo 取消当前操作，恢复折叠与全开，清空本次生产/训练记录和计数，保留零件库及文档，保留 commands 审计数组。当前顶栏在 sim=true 时依次发送 reset_demo、reset_estop；sim=false 时只在急停中经确认发送 reset_estop。

以上冻结、折叠和恢复是现有模拟行为，不能直接映射为真机断电或自动归位。

## 8. 错误与连接通知

| `code` | 含义 | 现有示例 |
|---|---|---|
| ok | 已接受或完成当前请求 | 空 msg |
| offline | 数据源未启动或已停止 | 连接已关闭 |
| estop | 正在急停，不接受该命令 | 请先解除急停 |
| busy | 生产、拍照或训练互斥 | 正在执行其他操作 |
| not_found | 读取对象或生产配方不存在 | 文档不存在 / 配方不存在 |
| invalid_args | 新建或重训草稿无效 | 请检查名称、编号和训练对象 |
| unknown_command | 无此命令 | 未知指令 |
| network | 仅已有 HTTP 适配器的网络或 JSON 解析异常 | 本地异常文本 |

network 是适配器本地生成的 `{ok:false,code:"network",msg}`，当前缺少 v、seq；不是后端应答模板。HTTP 适配器目前直接解析响应 JSON，没有按 HTTP 状态码额外分类。

本地连接通知形状为 `{type:"link",online:boolean,reason:string}`，不带 v/seq/t，也不要求主机通过 WebSocket 发送。模拟 reason 为 connected/stopped；已有网络适配器另有 connecting、message、timeout、closed、error、connect_failed。

当前 store 不处理线上 `error` 消息，也没有 failed/cancelled 状态或训练失败事件。后端不能只发送一条自定义错误消息，就认为当前页面会停止等待并显示原因。

## 9. 去重、统计与重连限制

store 先比较 t，t 相同时再比较 seq；重复或更旧的消息忽略。selfcheck_item 按 run_id+item，文档按 type+id，run_done 按 run_id，train_done 按 train_id 分别比较，其余按 type 比较。

生产中间结果须匹配当前 run_id，step_state 还须匹配当前工序、步数和零件。run_done 去重只防止重复计数，较新同 ID 结果会替换记录，不等于后端请求幂等。train_progress 按轮次合并，完成后的同 train_id 迟到进度不再接受。

demo_reset 的 t/seq 成为清空边界，边界以前的迟到消息全部忽略。模拟 run_id、train_id 在同一实例中递增、不因重置复用。

生产与训练记录目前只在浏览器内存中，没有历史查询端点、持久化、事件补发或完整快照协议。掉线仅影响在线判定，不能据此推断机械臂已经停止；刷新会重新建立模拟实例。

## 10. 接真实后端前还要补的接线

这张表列出现有实现的边界，避免后端提供了字段、页面却用不上。

| 项目 | 当前情况 | 实际接线时所需工作 |
|---|---|---|
| 主机地址 | main 固定创建 mock，设置页只读 | 启用真实数据源及地址配置 |
| 相机画面 | 生产页画的是本地 SVG 工作台，未加载 camera.url | 接视频或图片，并关联识别帧 |
| 工装与零件位置 | workspace 从本地 fixtures 初始化，没有线上更新消息 | 增加真实物体位置及模型映射 |
| 硬件参数 | 110 mm 夹爪、关节限位、TCP 来自 arm-params.js | 与实机统一，不能只改 hello |
| 置信度和检查缺测 | confidence 直接乘 100；检查失败直接调用数值 toFixed | 增加 unknown/null 显示，不能直接发送空值 |
| 执行失败 | 没有完整失败终态 | 补失败、取消和恢复约定 |
| 断线与记录 | 无 session、请求去重、持久化或任务快照 | 主机和数据源共同补齐 |

上述扩展另见[节点④设备层任务书](路演/tasks/节点4-设备层与后端接入任务书.md)。本文保留现有 v1 事实，扩展方案不能冒充当前已支持字段。
