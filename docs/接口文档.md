## 2. 职责边界与末端位置

```text
浏览器面板 ← WebSocket 状态、结果、画面地址 ← 另一台主机 ← 机械臂、手眼相机、激光
浏览器面板 → HTTP 指令                    → 另一台主机 → 机械臂、激光
```

面板只显示数据和下发指令。轨迹记录与回放、节点分段、修正量计算、校准、光点识别、深度处理、偏差计算和大模型都由另一台主机完成。激光开关由面板发起，主机转发给硬件并实施本地安全保护。面板不下发逐轴目标角，也不直接访问电机或相机驱动。

末端位置支持两种数据来源：面板由原始 `q` 做正运动学；主机可发送算好的 `end_base_mm` 供核对。当前画轨迹优先且只使用面板计算的夹持中心 `tcp`，不使用动画平滑后的角度。`end_base_mm` 在模拟实现中指官方 `end_link` 参考点，不能直接当作 `tcp`；核对时双方要先选同一参考点。

当前面板保留主机的 `end_base_mm`，尚无自动数值比对或缺失 `q` 时的坐标回退显示。示范样本无效、缺轴、越界或时间间隔超过 500 ms 时，路径断开，不补 0、不裁剪角度。显示用安装台不进入运动学。夹持中心、相机、激光的安装变换取自 `arm-params.js`，其中照片估算和占位量仍待实测或标定。

## 3. 传输、地址与 CORS

### 3.1 WebSocket 与 HTTP

主机 → 面板：局域网 WebSocket，每个文本消息是一个 UTF-8 JSON 对象，无 CRC 后缀。面板 → 主机：HTTP `POST /api/v1/command`，请求头 `Content-Type: application/json`，响应也为 JSON 对象。

面板地址栏用 `?backend=ws://主机:端口/路径` 指定主机。`ws` 对应 `http`，`wss` 对应 `https`，主机名和端口不变；命令路径固定为 `/api/v1/command`，原 WebSocket 路径、查询串和片段全部丢弃。例如 `ws://example.invalid:9000/telemetry?room=demo` 对应 `http://example.invalid:9000/api/v1/command`。示例域名不是设备地址。

没有 `backend` 参数时才使用浏览器内模拟主机；给了参数连接失败就显示离线，不回退到模拟。参数只能为 `ws://` 或 `wss://`。HTTPS 面板应配合 WSS、HTTPS 画面地址使用。换成直连时只换传输层，消息字段和单位不变；当前面板没有串口或 USB 适配器，直连须由适配层提供相同消息接口。

### 3.2 跨源响应

主机必须允许面板实际所在源。`Origin` 是协议、主机、端口的组合，不含路径。对命令的 `OPTIONS` 预检响应和实际 `POST` 响应，按下表配置；预检可返回 HTTP 204。

| 响应头 | 值 | 用途 |
|---|---|---|
| `Access-Control-Allow-Origin` | 面板的准确 Origin，例如 `http://localhost:8000` | 允许该面板读取响应；主机核对允许来源后返回 |
| `Vary` | `Origin` | 按来源区分缓存 |
| `Access-Control-Allow-Methods` | `POST, OPTIONS` | 允许命令与预检 |
| `Access-Control-Allow-Headers` | `Content-Type` | 允许 JSON 请求头 |
| `Content-Type` | `application/json; charset=utf-8` | 实际 POST 响应格式；空预检响应可省略 |

当前请求未设置跨源凭据、授权头或令牌，不要求 `Access-Control-Allow-Credentials`。认证方式若有需求需另行确认。WebSocket 握手由主机检查 `Origin`，不能靠上述 CORS 响应头代替握手检查。

## 4. 公共约定、关节与缺测

### 4.1 公共消息字段

每条主机推送均含下表 4 个必填字段；第 5 节各消息字段表都继承本表。主机应保证 JSON 数字有限，不发送 NaN、Infinity 或重复键。

| 名称 | 类型 | 单位 | 取值范围 | 是否必填 | 说明 |
|---|---|---|---|---|---|
| `v` | 整数 | 无 | 1 | 是 | 协议版本 |
| `type` | 字符串 | 无 | 第 5 节的 10 种消息类型 | 是 | 消息名称 |
| `seq` | 整数 | 无 | 1 至 9007199254740991 | 是 | 主机所有推送共用递增序号；当前未定义回绕 |
| `t` | 整数 | ms | 13 位 Unix 毫秒 | 是 | 主机时钟的消息时间；样本和节点同样使用 Unix 毫秒 |

只有一种时间格式：Unix 毫秒。持续时长使用 `ttl_ms`、`remaining_ms` 等字段，不能装入 `t`。主机时钟是否已对时待确认。归并同一结果时优先比较 `t`，同时间再比较 `seq`，重复或更旧消息不覆盖已有结果。不同节点的迟到结果可补齐历史。

真实 HTTP 请求的 `t` 由浏览器 `Date.now()` 生成，模拟请求的 `t` 由模拟主机时钟生成；应答没有 `t`。因此“主机时钟”严格适用于主机推送，不能假定真实请求的时钟已与主机一致。激光不一致告警只比较面板本地的指令时刻与收到 `laser_state` 的时刻，主机 `t` 不参与。主机不要仅凭请求的 `t` 判定有效时长，应从接收指令时开始本地倒计时。

### 4.2 坐标、单位与有效性

空间坐标均为 URDF 的 `base_link`，Z 向上，三维向量按 `[x, y, z]` 排列。消息中的空间长度、深度和夹爪开口用 mm；关节角 `q` 用 rad、速度 `dq` 用 rad/s。主机负责把编码器零位和正方向换算为 URDF 约定，面板不再做旧版的零位或正负号转换。关节卡片把 rad 格式化为角度显示，不改变运动学输入。

修正记录 `items[].delta` 是当前实现的单位例外：它由同项 `unit` 明确指定，模拟主机实际发送 `deg`，面板也支持按原单位显示 `rad` 和 `mm`。不得把修正表中的角度数值直接装入 `q`。

像素坐标按 `[u, v]` 排列，单位 px，图像左上角为原点，向右、向下为正。`dev_mm = spot_base_mm − ref_spot_base_mm`，`dev_norm_mm` 是该三维向量的欧氏长度。偏差由主机算，面板不从像素距离换算 mm。只得到二维测量时不能把未知 Z 填成 0，三维测量应报无效，二维模式另待双方确认。

缺测数值用 `null`，对应 `valid` 置 false，不能用 0 冒充。关节状态的 `valid` 是 6 元布尔数组，测量结果的 `valid` 是一个布尔值；两者不能混用。夹爪另用 `gripper_valid`。速度、电流或温度缺测时也填 `null` 并将该轴 `valid` 置 false；当前接口没有分别表示这三类量有效性的位图，面板会一并标记该轴无效。样本和节点可带 6 元 `valid`，省略仅表示该组数据全有效。

### 4.3 关节顺序与限位

所有关节数组固定为 6 元，顺序如下。限位直接取自 `arm-params.js` 的公开 URDF 设计值，尚未逐轴实测；主机应另行实施真实安全范围，不能把显示范围当作保护实现。

| 数组下标 | 名称 | 标识 | 下限（rad） | 上限（rad） |
|---|---|---|---|---|
| 0 | J1 底座 | `joint1` | -2.8 | 2.8 |
| 1 | J2 大臂 | `joint2` | -3.14 | 0 |
| 2 | J3 小臂 | `joint3` | -3.14 | 0 |
| 3 | J4 腕俯仰 | `joint4` | -1.87 | 1.57 |
| 4 | J5 腕偏摆 | `joint5` | -1.57 | 1.57 |
| 5 | J6 腕旋转 | `joint6` | -3.14 | 3.14 |

夹爪 `gripper_mm` 暂按两指内侧间距定义，范围 0 至 57 mm；单指设计行程 0 至 28.5 mm。自制夹指安装后的实际零开口和有效范围待确认。夹爪不占关节数组的第 7 项。本协议没有独立夹爪运动指令，开合随示范与练习由主机执行。

### 4.4 关联规则

`demo_id` 标识示范；`pass` 从 1 开始表示本次练习的遍数，`node` 引用示范节点的 `id`。当前面板按 `(pass, node)` 保存节点结果，按 `pass` 保存每遍汇总和修正；后两类消息没有 `demo_id`。主机必须按连接顺序发送模式变化与本轮数据，不把旧示范或上次练习的迟到结果混入新一轮。面板收到进入示范或新开始练习的模式变化时会清空上一轮练习记录。

### 4.5 面板本地通知

`link` 和 `panel_laser` 不是线上消息，不要求主机发送，也不计入 10 种消息。它们不带完整的公共消息头，不作为 JSON 报文示例。

| 通知 | 字段 | 来源与含义 |
|---|---|---|
| `link` | `type`、`online`、`reason` | 数据源生成连接状态；`online` 为布尔，`reason` 为连接、关闭或超时原因 |
| `panel_laser` | `type`、`want`、`t`、`seq` | 面板记录激光期望值；`want` 为布尔，供回报不一致检测 |

## 5. 主机推送消息

以下方向均为主机 → 面板，公共必填字段见 4.1。字段表中的“是，可 null”表示键必须存在，值可以缺测。嵌套表用独立字段名，所在对象由表前说明确定。

### 5.1 `hello`：连接信息

首次连接、重连及配置变化时发送。应先发此消息，再发状态和结果；面板须已有 `hello` 且链路在线才显示为可用。

| 名称 | 类型 | 单位 | 取值范围 | 是否必填 | 说明 |
|---|---|---|---|---|---|
| `proto` | 整数 | 无 | 1 | 是 | 内部协议声明；应与 `v` 一致 |
| `host_version` | 字符串 | 无 | 非空版本标识 | 是 | 主机软件版本；模拟为 mock-v1 |
| `arm` | 对象 | 无 | 见下表 | 是 | 机械臂信息 |
| `threshold_mm` | 数值 | mm | 大于 0；默认 5 | 是 | 每遍偏差阈值，面板用于曲线及提示 |
| `camera` | 对象 | 无 | 见下表 | 是 | 图像流及坐标尺寸 |
| `sim` | 布尔 | 无 | true / false | 是 | 模拟必须为 true；真机为 false |
| `laser_ttl_ms` | 数值 | ms | 大于 0；当前 3000 | 是 | 主机声明的激光有效时长 |
| `node_timeout_ms` | 数值 | ms | 大于 0；当前 2000 | 是 | 主机声明的节点结果等待时长 |

`arm` 对象：

| 名称 | 类型 | 单位 | 取值范围 | 是否必填 | 说明 |
|---|---|---|---|---|---|
| `model` | 字符串 | 无 | 非空名称 | 是 | 当前为 reBot Arm B601-DM |
| `joints` | 整数 | 个 | 6 | 是 | 只计转动关节，不含夹爪 |

`camera` 对象：

| 名称 | 类型 | 单位 | 取值范围 | 是否必填 | 说明 |
|---|---|---|---|---|---|
| `url` | 字符串或 null | 无 | 浏览器可 GET 的 HTTP(S) 地址 | 是，可 null | 建议绝对地址；无流用 null |
| `format` | 字符串或 null | 无 | 默认约定 mjpeg；无流为 null | 是，可 null | 当前页面直接作为图片加载，不按格式切换播放器 |
| `width` | 正整数 | px | 大于 0；模拟默认 640 | 有画面或像素结果时是 | 原始图像宽度 |
| `height` | 正整数 | px | 大于 0；模拟默认 480 | 有画面或像素结果时是 | 原始图像高度 |

面板读取 `threshold_mm`。激光守护器按最新归并的 `hello` 更新时长：`laser_ttl_ms`、`node_timeout_ms` 各自为有限正数时采用，否则分别回退到 3000 ms、2000 ms；续期间隔为 `min(1000, laser_ttl_ms / 3)` ms。未收到 hello 时使用默认值。页面恢复操作重建守护器时沿用已收到的 hello；运行中更新时长会重排计时，节点等待仍从原开光时刻计算。

```json
{"v":1,"type":"hello","seq":1,"t":1794614400000,"proto":1,"host_version":"example-v1","arm":{"model":"reBot Arm B601-DM","joints":6},"threshold_mm":5,"camera":{"url":"http://example.invalid:9000/camera.mjpg","format":"mjpeg","width":640,"height":480},"sim":false,"laser_ttl_ms":3000,"node_timeout_ms":2000}
```

### 5.2 `joint_state`：关节状态

建议 30 Hz，模式、安全状态、节点到达或离开时立即补发。模拟默认 20 Hz，面板不要求固定帧率。

| 名称 | 类型 | 单位 | 取值范围 | 是否必填 | 说明 |
|---|---|---|---|---|---|
| `mode` | 字符串 | 无 | idle / demo / practice / estop / fault | 是 | 空闲、示范中、练习中、急停、故障 |
| `q` | 6 元数值或 null 数组 | rad | 各轴见 4.3 | 是 | URDF 顺序的原始关节角 |
| `dq` | 6 元数值或 null 数组 | rad/s | 有限有符号值，上限待确认 | 是 | 实测角速度 |
| `current` | 6 元数值或 null 数组 | A | 有限有符号值，量程待确认 | 是 | 各关节电流；正负号与测量位置待确认 |
| `temp` | 6 元数值或 null 数组 | °C | 有限值，量程待确认 | 是 | 各关节温度 |
| `valid` | 6 元布尔数组 | 无 | 每项 true / false | 是 | 各轴数据是否有效；与数组下标对应 |
| `gripper_mm` | 数值或 null | mm | 0 至 57 | 是，可 null | 两指内侧间距 |
| `gripper_valid` | 布尔 | 无 | true / false | 是 | 夹爪数据是否有效 |
| `pass` | 正整数或 null | 遍 | 从 1 开始 | 是，可 null | 练习中当前遍数，其余为 null |
| `node` | 正整数或 null | 无 | 示范节点 `id` | 是，可 null | 当前测量节点；移动途中可为 null |
| `settled` | 布尔 | 无 | true / false | 是 | 当前节点已到达且停稳；由主机保证 |
| `fault` | 字符串或 null | 无 | 主机故障标识；正常为 null | 是，可 null | 非空即禁用训练按钮；硬件码待确认 |
| `end_base_mm` | 3 元数值数组或 null | mm | 有限坐标 | 否 | 可选的 end_link 位置；当前模拟遥测不发送 |

停稳判据（位置误差、速度、持续时间）由主机确定，待确认；不能用收到运动指令代替停稳。关节和夹爪缺测时即使模式仍是 idle，主机也必须拒绝不安全动作，不能依赖面板逐项验证保护硬件。

```json
{"v":1,"type":"joint_state","seq":2,"t":1794614400100,"mode":"practice","q":[0,-1.57,-1.57,0,0,0],"dq":[0,0,0,0,0,0],"current":[0.2,0.3,0.3,0.2,0.2,0.2],"temp":[28,29,29,28,28,28],"valid":[true,true,true,true,true,true],"gripper_mm":30,"gripper_valid":true,"pass":1,"node":1,"settled":true,"fault":null}
```

缺测示例：

```json
{"v":1,"type":"joint_state","seq":3,"t":1794614400200,"mode":"fault","q":[0,-1.57,null,0,0,0],"dq":[0,0,null,0,0,0],"current":[0.2,0.3,null,0.2,0.2,0.2],"temp":[28,29,null,28,28,28],"valid":[true,true,false,true,true,true],"gripper_mm":null,"gripper_valid":false,"pass":null,"node":null,"settled":false,"fault":"example_joint_unavailable"}
```

### 5.3 `demo_trajectory`：示范轨迹

结束示范后发送完整轨迹；重连后重发最新一份。样本按 `t` 排列，节点与样本使用同一个时间基准。主机记录人手扶臂的 6 轴数据并自动分段；节点数由主机决定，模拟为 4 个。

| 名称 | 类型 | 单位 | 取值范围 | 是否必填 | 说明 |
|---|---|---|---|---|---|
| `demo_id` | 字符串 | 无 | 非空且标识本份示范 | 是 | 模拟为 mock-1 等 |
| `samples` | 对象数组 | 无 | 按时间排列，非空 | 是 | 每帧原始数据，见下表 |
| `nodes` | 对象数组 | 无 | 自动分段的节点列表，非空 | 是 | 节点 id 不重复，按时间排列 |

`samples[]` 字段：

| 名称 | 类型 | 单位 | 取值范围 | 是否必填 | 说明 |
|---|---|---|---|---|---|
| `t` | 整数 | ms | 13 位 Unix 毫秒 | 是 | 原始采样时间 |
| `q` | 6 元数值或 null 数组 | rad | 各轴见 4.3 | 是 | 原始采样角度 |
| `gripper_mm` | 数值或 null | mm | 0 至 57 | 是，可 null | 同时刻的夹爪开口 |
| `valid` | 6 元布尔数组 | 无 | 每项 true / false | 否 | 无效帧须提供；省略表示全有效 |
| `gripper_valid` | 布尔 | 无 | true / false | 否 | 开口缺测时应给 false；当前轨迹计算不读取开口 |
| `end_base_mm` | 3 元数值数组或 null | mm | 有限坐标 | 否 | 主机算好的 end_link，当前仅保留供核对 |

`nodes[]` 包含样本表的 `t`、`q`、`gripper_mm` 及可选有效性字段，另含：

| 名称 | 类型 | 单位 | 取值范围 | 是否必填 | 说明 |
|---|---|---|---|---|---|
| `id` | 正整数 | 无 | 本份示范内唯一 | 是 | 后续消息用 `node` 引用 |
| `gripper_state` | 字符串或 null | 无 | open / closed；缺测为 null | 是，可 null | 夹爪状态；模拟以开口小于 20 mm 标 closed，不是硬件判据 |
| `ref_spot_base_mm` | 3 元数值数组或 null | mm | base_link 有限坐标 | 是，可 null | 示范光点基准位置；不可伪造 |
| `ref_spot_px` | 2 元数值数组或 null | px | 图像范围内；无结果为 null | 是，可 null | 示范光点在共同投影平面上的像素坐标，见第 9 节 |
| `end_base_mm` | 3 元数值数组或 null | mm | base_link 有限坐标 | 否 | 节点 end_link 参考点；模拟实际发送 |

当前节点没有单独的基准光点有效位；基准缺失用 null，随后该节点 `node_result.valid` 必须为 false。不要用关节 `valid` 冒充光点有效性。示例为节选规模的完整对象，实际主机应发送记录到的全量样本。

```json
{"v":1,"type":"demo_trajectory","seq":4,"t":1794614400500,"demo_id":"example-1","samples":[{"t":1794614400000,"q":[0,-1.57,-1.57,0,0,0],"gripper_mm":30},{"t":1794614400300,"q":[0.02,-1.55,-1.56,0.01,0.01,0.01],"gripper_mm":20}],"nodes":[{"id":1,"t":1794614400300,"q":[0.02,-1.55,-1.56,0.01,0.01,0.01],"gripper_mm":20,"gripper_state":"open","ref_spot_base_mm":[420,10,230],"ref_spot_px":[320,240],"end_base_mm":null}]}
```

### 5.4 `node_result`：节点测量结果

每遍每个测量节点发一次，包括测量失败。到位后先发 `joint_state` 的 `settled:true`，等面板开激光再测。模拟在开光后约 400 ms 出结果；未开光则等到节点等待期限，报光点未找到。结果必须带同一个 `(pass, node)`，面板才能关掉该节点的激光。

| 名称 | 类型 | 单位 | 取值范围 | 是否必填 | 说明 |
|---|---|---|---|---|---|
| `pass` | 正整数 | 遍 | 从 1 开始 | 是 | 所属遍数 |
| `node` | 正整数 | 无 | 已公布的节点 `id` | 是 | 所属节点 |
| `spot_px` | 2 元数值数组或 null | px | 同共同投影平面的图像范围 | 是，可 null | 实测光点坐标 |
| `depth_mm` | 数值或 null | mm | 大于 0 | 是，可 null | 光点的相机深度；深度定义与传感器处理待确认 |
| `spot_base_mm` | 3 元数值数组或 null | mm | 有限坐标 | 是，可 null | 实测光点在 base_link 的位置 |
| `ref_spot_base_mm` | 3 元数值数组或 null | mm | 有限坐标 | 是，可 null | 同一示范节点的基准位置 |
| `dev_mm` | 3 元数值数组或 null | mm | 有限有符号值 | 是，可 null | 实测位置减基准位置 |
| `dev_norm_mm` | 数值或 null | mm | 大于等于 0 | 是，可 null | 三维偏差大小 |
| `valid` | 布尔 | 无 | true / false | 是 | 本节点测量是否可用，不是 6 元数组 |
| `invalid_reason` | 字符串或 null | 无 | 有效时 null；无效时原因标识 | 是，可 null | 模拟实际为 spot_not_found；其他主机原因待确认 |
| `image_url` | 字符串或 null | 无 | 可访问的 HTTP(S) 图片地址 | 是，可 null | 本次测量截图；当前页面保留但不显示 |
| `end_base_mm` | 3 元数值数组或 null | mm | 有限坐标 | 是，可 null | 测量姿态的 end_link，由主机算；不等于光点 |

有效测量的坐标、深度、向量和模长必须相符。无效时保留已知的基准及末端位置，失败的观测量和偏差用 null，不纳入平均值。当前画面显示最近一条有效测量，失败消息不会清除先前光点，因此不能把仍可见的旧光点当作本节点测量成功。

```json
{"v":1,"type":"node_result","seq":5,"t":1794614401400,"pass":1,"node":1,"spot_px":[324,243],"depth_mm":250,"spot_base_mm":[423,14,230],"ref_spot_base_mm":[420,10,230],"dev_mm":[3,4,0],"dev_norm_mm":5,"valid":true,"invalid_reason":null,"image_url":"http://example.invalid:9000/images/example-1/pass-1/node-1.jpg","end_base_mm":null}
```

```json
{"v":1,"type":"node_result","seq":6,"t":1794614403400,"pass":1,"node":2,"spot_px":null,"depth_mm":null,"spot_base_mm":null,"ref_spot_base_mm":[430,15,240],"dev_mm":null,"dev_norm_mm":null,"valid":false,"invalid_reason":"spot_not_found","image_url":null,"end_base_mm":null}
```

### 5.5 `pass_result`：每一遍的结果

走完本遍全部节点后发送。停止或急停中断本遍时，模拟不生成完整遍结果；面板只显示已收到的节点和此前完成遍。

| 名称 | 类型 | 单位 | 取值范围 | 是否必填 | 说明 |
|---|---|---|---|---|---|
| `pass` | 正整数 | 遍 | 从 1 开始 | 是 | 已完成遍数 |
| `max_mm` | 数值或 null | mm | 大于等于 0 | 是，可 null | 有效节点偏差模长的最大值 |
| `mean_mm` | 数值或 null | mm | 大于等于 0 | 是，可 null | 有效节点偏差模长的算术平均值 |
| `valid_nodes` | 整数 | 个 | 0 至 total_nodes | 是 | 有效测量节点数 |
| `total_nodes` | 正整数 | 个 | 示范节点总数 | 是 | 本遍应测的节点总数 |
| `below_threshold` | 布尔 | 无 | true / false | 是 | 全部节点有效且 max_mm 严格小于阈值时为 true |

没有有效节点时两个偏差值为 null，`below_threshold` 为 false。面板优先使用主机的布尔 `below_threshold`；未提供合法布尔值时，按“最大偏差 ≤ 阈值且全部节点有效、节点总数大于 0”计算。模拟主机仍按上表的严格小于生成回报，面板尊重该值。第二数据格主数字仍为平均偏差，颜色和提示使用整遍达标结果，例如“✓ 达标（最大 ≤ 5 mm）”或“▲ 未达标（最大 6.9 mm）”；全无效时仍提示未达标，缺测数字显示横线。

```json
{"v":1,"type":"pass_result","seq":7,"t":1794614410000,"pass":1,"max_mm":5,"mean_mm":5,"valid_nodes":1,"total_nodes":2,"below_threshold":false}
```

### 5.6 `correction`：修正记录

本遍结束并完成修正决策后发送，通常紧随 `pass_result`。`pass` 指产生该决策的一遍；模拟主机把修正用于下一遍的目标角。大模型说明来自主机，面板按纯文本显示，不执行其中的指令或 HTML。

| 名称 | 类型 | 单位 | 取值范围 | 是否必填 | 说明 |
|---|---|---|---|---|---|
| `pass` | 正整数 | 遍 | 从 1 开始 | 是 | 修正所属遍 |
| `applied` | 布尔 | 无 | true / false | 是 | 是否已采纳修正；不是已完成下一遍的证明 |
| `items` | 对象数组 | 无 | 可为空 | 是 | 逐项修正，见下表 |
| `llm_text` | 字符串 | 无 | 说明文字，可为空 | 是 | 主机给出的说明；模拟为固定模板，不调用大模型 |

`items[]` 字段：

| 名称 | 类型 | 单位 | 取值范围 | 是否必填 | 说明 |
|---|---|---|---|---|---|
| `target` | 字符串 | 无 | 被修正对象的名称 | 是 | 模拟为 J1；不要当作新的运动命令 |
| `delta` | 数值 | 由 unit 指定 | 有限有符号值 | 是 | 修正后减修正前 |
| `unit` | 字符串 | 无 | rad / mm；兼容现有 deg 或 ° | 是 | 模拟当前用 deg，面板只格式化显示 |
| `note` | 字符串 | 无 | 可为空的简短说明 | 是 | 当前面板从“节点 N”文字提取节点标签，未有结构化节点字段 |

```json
{"v":1,"type":"correction","seq":8,"t":1794614410000,"pass":1,"applied":true,"items":[{"target":"J1","delta":-0.6,"unit":"deg","note":"节点 1 的下一遍目标角修正"}],"llm_text":"本遍节点 1 偏差 5 mm，下一遍 J1 目标角减小 0.6 °。"}
```

### 5.7 `laser_state`：激光状态

首次连接、重连、开关变化、续期、急停、到期关闭时立即发送，并建议每 1 s 更新一次剩余时长。模拟即按此方式发送。

| 名称 | 类型 | 单位 | 取值范围 | 是否必填 | 说明 |
|---|---|---|---|---|---|
| `on` | 布尔 | 无 | true / false | 是 | 主机回报的开关状态；急停时必须为 false |
| `source` | 字符串 | 无 | sensed / software | 是 | 实际检测或软件记录，见第 7 节 |
| `remaining_ms` | 数值 | ms | 大于等于 0 | 是 | 本地有效时长的剩余值，关闭时为 0 |
| `reason` | 字符串 | 无 | 状态变化原因 | 是 | 模拟使用 initial、laser_on、laser_renew、command、ttl_expired、estop、stopped |

`reason` 不是错误码；即使值与指令名称相同也不表示发起新指令。实际检测仍开而有效时长已到期时，应如实报 `on:true`、剩余 0，并上报故障，不能伪报已关闭。

```json
{"v":1,"type":"laser_state","seq":9,"t":1794614410100,"on":false,"source":"software","remaining_ms":0,"reason":"command"}
```

### 5.8 `event`：事件

状态、流程或需提示的信息发生时发送，不设固定频率。

| 名称 | 类型 | 单位 | 取值范围 | 是否必填 | 说明 |
|---|---|---|---|---|---|
| `name` | 字符串 | 无 | 非空事件名 | 是 | 模拟实际发 pass_finished；其他名称由主机定义 |
| `text` | 字符串 | 无 | 面向操作人的简短说明 | 是 | 面板直接显示纯文本 |
| `level` | 字符串 | 无 | info / warning / error | 是 | warning、error 使用警示样式 |

面板还会根据模式变化、连接变化生成本地事件，并根据遍结果和修正记录生成列表项。收到 `name:pass_finished` 的原始事件会从列表过滤，改用 `pass_result` 生成结束文字，避免重复。

```json
{"v":1,"type":"event","seq":10,"t":1794614410100,"name":"pass_finished","text":"第 1 遍结束，1/2 个节点测量有效。","level":"warning"}
```

### 5.9 `heartbeat`：心跳

每 1 s 发送一次，包括空闲和急停状态；只有公共字段，无额外字段。面板不需要回一条 JSON 心跳。

| 名称 | 类型 | 单位 | 取值范围 | 是否必填 | 说明 |
|---|---|---|---|---|---|
| `v`、`type`、`seq`、`t` | 见 4.1 | 见 4.1 | type 固定为 heartbeat | 是 | 无其他负载 |

```json
{"v":1,"type":"heartbeat","seq":11,"t":1794614411000}
```

### 5.10 `error`：异步错误

无法归属某个 HTTP 请求或运行中出现错误时发送；请求拒绝仍使用 HTTP 应答。当前模拟主机只返回失败应答，不主动推送 `error`；面板可以接收并显示此类型。

| 名称 | 类型 | 单位 | 取值范围 | 是否必填 | 说明 |
|---|---|---|---|---|---|
| `code` | 字符串 | 无 | 第 11 节已有码或主机扩展标识 | 是 | 不使用旧文档整数码 |
| `msg` | 字符串 | 无 | 面向操作人的错误说明 | 是 | 建议用中文；不要只给内部堆栈 |

单独的 `error` 只增加事件，不会自动设置故障模式或停止激光。主机须同步执行保护并发送 `joint_state.mode:fault` 或 `estop` 以及 `laser_state`。

```json
{"v":1,"type":"error","seq":12,"t":1794614411200,"code":"estop","msg":"已急停，激光已关闭。"}
```

## 6. 面板指令与应答

### 6.1 公共请求与响应

以下 10 条指令方向都是面板 → 主机，使用 `POST /api/v1/command`；应答方向为主机 → 面板。应答不带 `type` 或 `t`。HTTP 应答和 WebSocket 状态到达顺序可能交错，面板显示以状态为准，不能把成功应答当作测量完成。

| 名称 | 类型 | 单位 | 取值范围 | 是否必填 | 说明 |
|---|---|---|---|---|---|
| `v` | 整数 | 无 | 1 | 请求、应答均是 | 协议版本 |
| `cmd` | 字符串 | 无 | 本节 10 条指令 | 请求是 | 操作名称 |
| `seq` | 正整数 | 无 | 不超过 9007199254740991 | 请求、应答均是 | 面板独立递增，主机原样回填；不等于推送序号 |
| `t` | 整数 | ms | 13 位 Unix 毫秒 | 请求是 | 当前由浏览器生成，见 4.1 |
| `ok` | 布尔 | 无 | true / false | 应答是 | 本次指令是否接受或完成设置 |
| `code` | 字符串 | 无 | 成功为 ok；失败见第 11 节 | 应答是 | 供程序判断 |
| `msg` | 字符串 | 无 | 简短说明，可为空 | 应答是 | 模拟成功时为空字符串 |

所有指令均可能遇到模拟未运行的 `offline`，或传输层生成的 `network`。急停期间，模拟主机除 `reset_estop` 外一律回 `estop`，包括 `laser_off` 和重复 `estop`；它在进入急停时已经关光并保持关闭。以下各条失败码在此公共规则之外列出。

当前 `fetch` 不检查 HTTP 状态码，只尝试解析 JSON；业务失败也必须返回上述对象，不要返回 HTML 错误页。网络异常或 JSON 解析失败时，数据源返回本地 `ok:false, code:network, msg`，没有 `v`、`seq`。请求没有显式超时、自动重试或幂等重放机制；无应答不代表未执行，主机应继续推送真实状态。超时、会话关联和重复指令策略待联调确认，不能依赖客户端 `seq` 全局唯一。

### 6.2 `demo_start`：开始示范

前置条件：在线、非急停、模式 idle，硬件允许人工示范。无附加参数。成功回 `ok`，立即推送 `mode:demo` 并开始记录。非 idle 回 `busy`；硬件保护由真主机检查，具体码待确认。模拟动作约 6 s 后停在终点，仍保持示范模式，直到收到结束指令。

```json
{"v":1,"cmd":"demo_start","seq":1,"t":1794614400000}
```

```json
{"v":1,"ok":true,"code":"ok","msg":"","seq":1}
```

### 6.3 `demo_stop`：结束示范

前置条件：在线、非急停；示范中才有状态改变。无附加参数。成功回 `ok`，示范中同时发送 `demo_trajectory` 和 `mode:idle`；非示范模式是成功空操作，不会终止练习。没有额外模拟失败码。模拟会排除动作走完后等待用户结束的静止尾段。

```json
{"v":1,"cmd":"demo_stop","seq":2,"t":1794614406000}
```

```json
{"v":1,"ok":true,"code":"ok","msg":"","seq":2}
```

### 6.4 `practice_start`：开始练习

前置条件：在线、非急停、idle 且已有示范。无附加参数，不接收遍数参数。成功回 `ok`，从第 1 遍开始，推送 `mode:practice`。非 idle 回 `busy`；无示范回 `no_demo`。当前面板未依据“无示范”禁用此按钮，主机必须验证。模拟会连续练习，直到停止；真实主机的总遍数待确认。

```json
{"v":1,"cmd":"practice_start","seq":3,"t":1794614407000}
```

```json
{"v":1,"ok":true,"code":"ok","msg":"","seq":3}
```

### 6.5 `practice_stop`：停止练习

前置条件：在线、非急停；练习中才有状态改变。无附加参数。成功回 `ok` 并推送 idle；其他模式是成功空操作。没有额外模拟失败码。模拟停止本身不关激光，面板收到离开 practice 的状态后由守护器另发 `laser_off`，真主机仍须执行到期关光与安全保护。

```json
{"v":1,"cmd":"practice_stop","seq":4,"t":1794614417000}
```

```json
{"v":1,"ok":true,"code":"ok","msg":"","seq":4}
```

### 6.6 `estop`：急停

前置条件：主机可接收请求；运行中也必须处理，不得因 busy 排队等待。无附加参数。成功回 `ok`，终止当前流程、进入 estop、立即关激光并推送状态。已急停时模拟回 `estop`，仍保持停机和关光；未运行回 `offline`。主机必须自行实施实际停机和关断，不能把 UI 禁用按钮当作硬件急停。

```json
{"v":1,"cmd":"estop","seq":5,"t":1794614418000}
```

```json
{"v":1,"ok":true,"code":"ok","msg":"","seq":5}
```

### 6.7 `reset_estop`：解除急停

前置条件：操作人已确认可以解除；真主机须确认故障解除、停止完成和激光关闭，实际判据待确认。无附加参数。模拟在 estop 时回 `ok` 并切到 idle，其他模式成功空操作，没有硬件检查。除公共离线/网络失败外暂无额外模拟码，真机解除失败的错误码待确认。解除后不续跑、不自动开光。

```json
{"v":1,"cmd":"reset_estop","seq":6,"t":1794614419000}
```

```json
{"v":1,"ok":true,"code":"ok","msg":"","seq":6}
```

### 6.8 `mark_node`：手动记节点（预留）

前置条件：主机明确支持手动节点后再启用，当前没有面板按钮。无已定义附加参数。模拟始终回 `unsupported`，急停和离线规则优先；当前没有可承诺的成功行为，勿将请求示例当作已支持。

```json
{"v":1,"cmd":"mark_node","seq":7,"t":1794614420000}
```

```json
{"v":1,"ok":false,"code":"unsupported","msg":"模拟主机自动分成 4 个节点","seq":7}
```

### 6.9 `laser_on`：开激光

前置条件：在线、非急停、硬件允许出光。面板手动开关在 practice、fault 中禁用；自动开光只在 practice 的节点停稳后触发。模拟接受所有非急停模式的开光，不验证硬件或停稳条件，真主机须补足保护。成功回 `ok` 并立即发 `laser_state`。附加失败码为 `ttl`。

| 参数 | 类型 | 单位 | 取值范围 | 是否必填 | 说明 |
|---|---|---|---|---|---|
| `ttl_ms` | 数值 | ms | 有限且大于 0；默认 3000 | 否，面板实际发送 | 从主机接收指令起计时；模拟未设上限，真机上限待确认 |

```json
{"v":1,"cmd":"laser_on","seq":8,"t":1794614421000,"ttl_ms":3000}
```

```json
{"v":1,"ok":true,"code":"ok","msg":"","seq":8}
```

### 6.10 `laser_renew`：续期

前置条件：在线、非急停且激光当前已开；面板按 `min(1000, laser_ttl_ms / 3)` ms 发送，默认每 1 s。参数 `ttl_ms` 的类型、范围、默认值同 `laser_on`。新截止时间为本次接收时刻加有效时长，不是在旧截止时间上累加；续期不重新开始节点测量。成功回 `ok` 并发状态。附加失败码：无效时长 `ttl`；已关闭 `laser_off`，不会自动重开。

```json
{"v":1,"cmd":"laser_renew","seq":9,"t":1794614422000,"ttl_ms":3000}
```

```json
{"v":1,"ok":true,"code":"ok","msg":"","seq":9}
```

### 6.11 `laser_off`：关激光

前置条件：无需已开；面板在断线时也尝试发送。无附加参数。成功回 `ok` 并发关闭状态；已关闭时也可成功。急停期间模拟回 `estop`，由急停入口保障保持关闭；其余没有附加模拟失败码。真实硬件关断失败必须如实回报，不得只更新软件记录后声称实际熄灭。

```json
{"v":1,"cmd":"laser_off","seq":10,"t":1794614423000}
```

```json
{"v":1,"ok":true,"code":"ok","msg":"","seq":10}
```

## 7. 激光控制与安全兜底

练习中，面板收到带 `pass`、`node`、`settled:true` 的最新关节状态，且该节点未测过，发送开光指令。同一节点收到 `node_result`，无论 `valid` 是真是假，或等待达到 `node_timeout_ms`（默认 2 s），立即发关光。节点离开、节点编号改变或不再停稳也会关闭，重复停稳帧不重复开光。

手动开关用于对准与调试，仅在在线、非练习、非急停、非故障时可用；打开后有醒目提示。进入练习会先结束手动开光，再由节点流程自动控制。无论手动还是自动，`hello.laser_ttl_ms`、`hello.node_timeout_ms` 的有限正数值覆盖默认 3000 ms / 2000 ms，各字段缺失或不合法时各自使用默认值；开光及续期请求携带选定的 TTL，续期间隔取 `min(1000, ttl / 3)` ms。

急停、故障、断线、离开主页、页面隐藏和关闭页面时，面板停止续期并尝试发 `laser_off`。连续 200 ms 内的重复安全关闭会合并。页面关闭时当前请求未设置 keepalive，不保证送达；不能依赖这最后一条请求关光。恢复页面后不会仅因继续收到停稳帧自动开光，须重新开始操作或显式手动打开。

主机必须独立承担以下兜底：收不到续期则到期自行关闭；急停立即关闭并保持；检测到面板断线立即关闭；主机重启默认关闭，不恢复旧开光请求。关断异常必须上报错误及真实状态。这些是对真实主机的要求；模拟用 `stop()` 和有效时长模拟关闭，没有物理检测能力。

面板显示以 `laser_state.on` 为准，不以按钮是否点过或 HTTP 是否成功为准。期望值变化时记录面板本地指令时刻 `panel_laser.t`，续期不重置它；归并 `laser_state` 时将调用方传入的面板本地接收时刻保存为 `received_at`，store 不读取时钟。两值不一致且 `received_at - panel_laser.t > 1000` ms 时显示“激光状态不一致”，主机消息的 `t` 仅用于消息排序。没有回报或只有指令前的旧回报时不触发；心跳不会代替激光回报推进此计时。主机须主动发初始状态并持续更新。

`source:sensed` 表示有实际检测，检测的是光输出还是供电需在联调中说明；`source:software` 仅表示软件记录或控制输出，不证明实际出光。模拟固定为 software。UI 当前不单独展示 source 和剩余时长，主机仍须准确提供；急停的正常回报应为 `on:false, remaining_ms:0`，实际关断失败不得伪报。

## 8. 示范与练习的时序

### 8.1 示范

```text
操作人             面板                         另一台主机
  │                 │ ← hello、laser_state、joint_state(idle)
  │ 点“示范”        │
  ├────────────────→│ → POST demo_start          │
  │                 │ ← 应答 ok                 │
  │ 扶臂运动        │ ← joint_state(mode=demo)   │ 记录原始关节与夹爪
  │                 │ ← 持续状态、heartbeat     │ 生成节点基准，方法待确认
  │ 再点“结束”      │ → POST demo_stop           │
  ├────────────────→│ ← 应答 ok                 │
  │                 │ ← demo_trajectory         │ 保存完整示范和节点
  │                 │ ← joint_state(mode=idle)  │
  │                 │ 用 q 做 FK，显示示范虚影  │
```

应答和状态不保证上图顺序。模拟只有点结束才生成示范，走完约 6 s 后等待；示范基准光点用运动学构造，不触发真实测量。当前守护器只在练习自动开光，示范时如何采集各节点的真实基准光点尚待确认，不能假定示范自动开光已实现。

### 8.2 练习

```text
操作人             面板                         另一台主机
  │ 点“练习”        │ → POST practice_start      │ 验证已有示范
  ├────────────────→│ ← 应答 ok                 │
  │                 │ ← joint_state(practice, pass=1)
  │                 │ ← joint_state(node=1, settled=true)

  │                 │ ← 应答、laser_state(on=false)
```

## 9. 手眼相机画面与截图

相机装在夹爪头上，跟随末端运动，具体型号待确认。主机负责 RGB、深度对齐和光点识别。实时取流地址由 `hello.camera.url` 给出；默认建议 MJPEG，`format:mjpeg`。建议先以 640 × 480 px、15 至 30 Hz 提供 RGB 预览，实际分辨率、帧率和带宽待联调确认，不能把建议当相机规格。

MJPEG 响应使用 `Content-Type: multipart/x-mixed-replace; boundary=frame`，每段为 `image/jpeg`；边界名与响应体一致。提供可直接放入 HTML 图片元素的流。当前没有 RTSP、WebRTC 或视频解码器，也不根据 `format` 选择播放器；单张 JPEG 地址只会按图片加载，不会自动轮询。模拟 `url`、`format` 均为 null，画面由页面绘制，不提供真实视频流。

地址建议为绝对 HTTP(S) URL。当前 `img.src` 直接使用 `url`，相对地址会相对面板地址解析，不会自动拼主机地址。图片不得依赖额外自定义请求头；其访问权限、跨源策略及 HTTPS 要与面板部署一致。图像原始尺寸优先取图片实际宽高，没有图片时取 `width`、`height`，最后回退到 640 × 480 px。像素结果须对应这套尺寸，不能混用缩略图坐标。

叠加层按当前 `(pass, node)` 取最新结果；有效时取示范节点的 `ref_spot_px` 与 `node_result.spot_px`，连线并标注 `dev_norm_mm`。无效时孪生清空 spots，相机不画光点、连线、箭头或偏差标签，在画面中央下方显示原因：`spot_not_found` → “未找到光点”、`depth_invalid` → “深度无效”、`timeout` → “测量超时”，其它 → “测量无效”。进入下一个节点后清除提示，尚未测量时不回退到旧光点；没有当前节点时保留最近结果的有效性。

面板没有重投影能力，也没有按截图时间锁定实时视频帧；相机运动时必须确认两种像素坐标是否位于同一投影平面。模拟统一投影到示范节点的相机平面；真实主机如何让当前图像与该平面对齐待确认，不能直接将两次不同相机姿态的原始像素相减当作物理偏差。

`image_url` 应指向该 `(demo_id, pass, node)` 测量对应的静态 JPEG 或 PNG，浏览器可直接 GET，返回正确图片类型；文件内容应固定，不随下一次测量覆盖。没有截图填 null，不发不存在的占位地址。建议地址含示范、遍和节点标识，截图的采样时间采用同一 Unix 毫秒基准与结果关联；保存多久、访问方式和过期行为待确认。当前面板只保留 `image_url`，没有截图查看入口。

## 10. 心跳、离线超时与重连

### 10.1 面板行为

主机每 1 s 发 `heartbeat`。面板超过 `offlineAfterMs`（默认 3 s）没收到任何 WebSocket 消息即视为离线，发 `{type:"link", online:false, reason:"timeout"}`，关闭当前 WebSocket 并按 `retryMs`（默认 1000 ms）重连。页面显示离线、停止续期并尝试发激光关闭。示范、练习、激光三个训练按钮全禁用，轨迹断开，旧数据不冒充新测量。

当前“按钮全禁用”的实际范围仅为训练模块的三个按钮。旧版急停、解除、版本下拉及断线横幅仍由旧后端连接控制，未跟随此主机的超时统一禁用或更新；主机自身必须在断线时保护。训练模块的急停点击会额外发送本协议 `estop` 和关闭请求；解除请求依赖旧急停状态通知，真实联动仍待验证。

数据源按任何消息到达刷新 3 s 看门狗，包含之后被 JSON 或版本检查丢弃的载荷；它只过滤非对象、数组和 `v !== 1`，没有完整字段校验。主机不能靠错误载荷维持链路，更不能据此假定数据有效。WebSocket 打开就发本地在线通知，显示层另外要求已有 hello，但当前重连没有强制清空旧 hello 或等待新关节状态。

### 10.2 主机侧要求

主机检测连接关闭、网络失联或激光有效时长到期后自行关闭激光，不等面板最后一条 HTTP 指令。主机仍有连接时继续发送心跳和真实安全状态；无有效测量要发 null 和有效性标志。停机、防坠与失联恢复条件由硬件方案确定，待确认。

当前面板没有反向 JSON 心跳。主机不能以“3 s 没收到 HTTP 命令”认定面板离线，因为空闲期间没有命令；应使用 WebSocket 连接状态及协议层 ping/pong 或链路保活检测，激光另有 3 s 租期兜底。主机保活策略和断线检测时限待确认。

### 10.3 重连流程

WebSocket 关闭、报错或消息静默超时后，面板按固定 `retryMs`（默认 1000 ms）间隔重试同一地址，不切换模拟。静默超时主动关闭连接并移除旧回调，旧连接的迟到消息不会恢复在线；新连接打开后发 `{type:"link", online:true, reason:"connected"}`。停止数据源会取消看门狗与重连任务。

真正重连成功后，主机应依次重发 `hello`、最新 `demo_trajectory`（存在时）、`laser_state` 和完整 `joint_state`，再恢复心跳。重连不自动恢复激光，也不得根据旧请求重新发起示范或练习。当前模拟 `start()` 只发 hello、关节、心跳、激光状态，停止再启动时不重发已有示范；真实主机须实现上述恢复要求。

当前没有会话 ID 或重启纪元；旧状态按 `t`、`seq` 比较后才覆盖。因此主机重连后应保持时间递增；主机时钟倒退或重启后序号与时间同时落后，面板可能保留旧状态，需要重新加载面板并重新确认运行状态。历史结果没有补发握手，刷新页面无法恢复所有已完成遍，恢复范围需另行约定。

## 11. 错误码表

以下字符串与现有实现一致。除 `network` 是真实数据源本地生成，其他列出的失败应答均可由模拟主机触发。`code` 是错误标识，`msg` 是给人看的说明；未知码显示通用失败并保留说明，不自动重试动作。

| 分类 | `code` | 实际触发 | 处理 |
|---|---|---|---|
| 成功 | `ok` | 指令接受、设置完成或允许的空操作 | 等待相应状态，不代替动作完成 |
| 协议 | `unknown_command` | 不认识的 cmd | 核对命令名，不执行 |
| 协议 / 能力 | `unsupported` | mark_node 尚未实现 | 保留自动分段 |
| 状态不允许 | `busy` | 非 idle 时开始示范或练习 | 先结束当前流程 |
| 状态不允许 | `no_demo` | 没有示范就开始练习 | 先完成示范 |
| 连接 | `offline` | 模拟主机未启动或已停止 | 恢复连接后重新确认状态 |
| 连接 | `network` | fetch 异常或响应 JSON 解析失败 | 结果未知，检查状态，不盲目重发 |
| 安全 | `estop` | 已急停时收到 reset_estop 之外的指令 | 保持停机、关光，确认条件后解除 |
| 激光参数 | `ttl` | ttl_ms 非有限数值或小于等于 0 | 修正有效时长 |
| 激光状态 | `laser_off` | 已关闭时请求续期 | 保持关闭，不把续期变成开启 |
| 硬件 | 待确认，无已实现固定码 | 电机、深度、供电、实际关断等异常 | 由主机提供真实 code、msg 和 fault，不编造厂家码 |
| 协议版本 / 格式 | 待确认，无已实现固定码 | 不支持的版本或坏 JSON | 当前面板丢弃推送；主机拒绝坏请求，具体应答码待确认 |

`spot_not_found` 是 `invalid_reason` 的测量原因；`ttl_expired` 是 `laser_state.reason` 的到期原因，均不是模拟 HTTP 错误 `code`。深度无效、无基准、限位和关断故障的具体标识仍待主机确认。不得照搬旧版整数码或把算法诊断标签当作电机错误码。

## 12. 版本、兼容规则与实现差异

本版本为 `v:1`、`proto:1`。允许增加不改变既有语义的可选字段；改变单位、坐标系、必填项、数组顺序或既有字段含义，应另定新版本并更新双方实现。不能在同一个字段里静默切换 rad 与角度，修正项只能按显式 `unit` 解释。未知消息类型不会更新业务槽位；未知字段可被保存但不保证显示。

面板当前只检查外层 `v`，未强校验 hello 的 `proto`、型号、关节数和完整 schema。主机仍必须发送合规数据并在主机侧验证指令。旧接口虽也写版本 1，但属于不同传输端点和数据模型，不能混发。

下表保留设计差异及处理状态，供联调核对。T6 已修补 D01、D04、D05 的静默重连、D07 的无效测量显示及 D10；其余行为保持现状。

| 编号 | 设计或目标 | 当前实现与对接处理 |
|---|---|---|
| D01 | 激光不一致告警不跨时钟比较 | 已按设计实现：比较面板本地指令时刻与 laser_state 的本地 received_at；主机 t 不参与告警 |
| D02 | 消息角度用 rad | q、dq 符合；模拟 correction.delta 用 deg，必须按 unit 读取 |
| D03 | 两种末端位置均支持，优先本地 FK | 图形仅用 q 算 tcp；主机 end_base_mm 是 end_link，尚无回退或自动比对 |
| D04 | 激光时长可配置并在 hello 声明 | 已按设计实现：合法正数覆盖默认 TTL / 节点超时；续期间隔 min(1000, ttl/3) ms |
| D05 | 静默超时主动重连；离线禁用操作 | 已按设计实现静默重连：关闭旧连接，按 retryMs 重试，连上发 online:true；仍只禁用三个训练按钮，旧急停、解除及断线横幅由旧连接控制 |
| D06 | 重连恢复最新示范与状态 | 真主机须重发；模拟重新 start 不重发示范，面板也未强制等待全套新快照 |
| D07 | 手眼画面反映当前节点测量 | 已按设计实现无效测量清屏：孪生清空 spots，相机隐藏光点和箭头并显示原因，下个节点清除提示；仍未按图像时刻锁帧或重投影，image_url 只保存，模拟无视频流 |
| D08 | 示范中取得真实光点基准 | 守护器只在练习自动开光；模拟基准由 FK 构造，真机示范如何测基准待确认 |
| D09 | T4 早期说明允许示范走完自动结束 | 决策 M7 已改为必须点击结束；模拟约 6 s 后停住等待，排除等待尾段 |
| D10 | 每遍达标按最大偏差和全部有效节点判定 | 已按设计实现：优先用 below_threshold，缺失时按最大 ≤ 阈值且全部节点有效计算；数据格主数字仍为平均值，提示统一为达标 / 未达标 |

模拟还有明确能力边界：关节状态默认 20 Hz（真机建议 30 Hz）；相机尺寸是模拟配置；不检查硬件解除急停条件；急停中拒绝关光指令但入口已关光；不主动推送 error。上述模拟行为不证明真实硬件保护已完成。
