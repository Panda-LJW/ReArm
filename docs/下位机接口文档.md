## 2. 系统边界

```text
下位机（电机、激光、急停、电源监测） ⇄ 上位机后端（Python / FastAPI） ⇄ 浏览器面板
                                             ↑
                                    摄像头（直接接上位机）
```

下位机执行关节动作、控制激光、执行本地保护并上报状态。摄像头不经过下位机。落点识别、预测、误差、诊断、标定、补偿学习、版本管理和自愈统计全部由上位机完成；固件不需要发送这些结果。

当前 `rearm/hw/real_arm.py`、`servo.py`、`laser.py` 都是抛出 `NotImplementedError` 的骨架，`build_app(sim=False)` 也尚未接通。浏览器 `/ws` 接收上位机的 `{kind, timestamp, data}` 事件；本协议的 `{v, type, ...}` 是另一层报文，不能直接送入现有 `/ws` 事件处理器。

`Shooter.shoot()` 先 `move_to()`，再 `read_state()`，然后开激光、用上位机相机观测，最后在 `finally` 里关激光。因此真机适配器的 `move_to()` 必须等到动作完成后返回。当前配置 `settle_seconds: 0.0`，不能用它假定真机已经稳定。真机稳定时间及到位判据待确认。

## 3. 通信方式选型

以下是工程选型比较，延迟取决于设备实现，尚未实测。

| 方式 | 接线与现场可靠性 | 延迟 | 带宽 | 调试难度 | 固件工作量 | 与现有代码的契合 |
|---|---|---|---|---|---|---|
| USB 串口（CDC 虚拟串口） | 一根 USB 线；需固定插头并处理拔插 | 通常适合本任务，受 USB 缓冲影响 | 满足本稿 50 Hz；实际吞吐待测 | 低，串口终端可读 | 需 CDC、行解析和 CRC | 已有 `pyserial`，仍需实现驱动 |
| TTL UART | TX/RX/GND；需核对电平、共地、线长和干扰 | 921600 bps 下传输时间可估算 | 8N1 理论 92160 字节/s | 低，USB-UART 加串口终端 | UART、行解析和 CRC | 可复用 `pyserial` 和串口报文 |
| TCP | 以太网需接口和地址配置；无线链路另评估 | 受缓冲、重传及网络影响 | 通常足够，按实际网络验证 | 中，需处理粘包与断线 | 网络栈、连接管理、行解析 | Python 标准库可接入；当前无设备 TCP 适配器 |
| WebSocket | 建立在 TCP 上；需配置服务地址 | 另有握手和消息开销 | 本任务数据量较小 | 中，浏览器可看消息 | 网络栈、握手及消息分帧 | 已有 `websockets`；`device-source.js` 已能只读遥测 |
| CAN 直连 | 上位机经 USB-CAN 直接驱动电机，不设下位机；需终端匹配和总线布线 | 取决于总线负载、适配器及主机调度 | 受 CAN 版本和总线速率限制 | 高，需核对电机协议 | 无下位机固件；主机需接管驱动与保护 | 当前无 CAN 适配器；不是本稿 JSON 接口的直接替换 |

推荐 USB 串口 CDC，串口设置采用 8N1；若改 TTL UART，采用 921600 bps、8N1、无硬件流控。CDC 的波特率设置是否影响实际传输由 USB 固件决定，联调时确认，不把 CDC 当作物理 UART。TTL 电平及接口针脚待确认，不直接连接未经核对的引脚。

每帧一行 JSON 文本，后接 `*`、CRC16 和 `\n`。任何串口工具都能直接看懂，路演现场便于排查；相同 `v` 下可追加不改变原语义的可选字段。接收方忽略未知可选字段；改变单位、字段含义或必填项必须升版本。

50 Hz、每帧约 300 字节是简化报文的初步预算，对应约 15000 字节/s、8N1 下约 150000 bit/s。**带齐本稿全部字段的报文会更长**，尤其上报 6 轴时不能继续按 300 字节估算。按单帧上限 1024 字节计算，50 Hz 为 51200 字节/s、512000 bit/s，约占 921600 bps UART 理论带宽的 56%，还需给应答、事件和系统缓冲留余量。完整示例的实际长度见第 10 节，最终频率以联调压测为准。

上位机验 CRC 后，可以把同一份 JSON 内容原样转发给浏览器，无需改字段。`modules/datasource/device-source.js` 的 `parseTelemetry` 已解析这个 JSON 结构，但直接调用 `JSON.parse()`，**不解析 `*CRC` 后缀**；转发前必须去掉后缀和行尾。目前没有实现串口到浏览器的转发服务，该模块只收不发，也不发送心跳或控制命令。联调前可用 `scripts/mock_device.py` 在本机模拟一路 WebSocket 遥测，验证显示端。

同一 JSON 格式也可运行在 TCP/WebSocket 上，届时去掉 CRC 后缀：TCP 仍每行一个 JSON，以 `\n` 分帧；WebSocket 每个文本消息一个 JSON 对象，不依赖行尾。资源紧张时可另定二进制承载，布局建议见附录 C，不能静默切换。

## 4. 帧格式

```text
<JSON>*<CRC16 四位大写十六进制>\n
```

使用 UTF-8，无 BOM；行尾为单字节 LF（`0x0A`），不附加 CR。单帧最长 1024 字节，包含 JSON、星号、4 位 CRC 和 LF，因此 JSON 最长 1018 字节。JSON 必须为对象，不得含实际换行，字符串换行使用转义序列；禁止 NaN/Infinity，禁止重复键。JSON 键顺序不限，但空格、中文编码和键顺序都会影响 CRC，接收端必须对收到的原始字节计算，不能先解析再序列化。

CRC16/CCITT-FALSE：多项式 `0x1021`，初值 `0xFFFF`，输入和输出不反射，最终异或 `0x0000`。范围为分隔符 `*` 之前的全部 JSON 字节，不含星号、CRC 和 LF。分隔符定位为行末 4 位 CRC 之前的最后一个 `*`，JSON 字符串中的星号属于被校验内容。标准校验向量 ASCII `123456789` 的结果为 `0x29B1`。

接收时累计到 LF 再验帧，允许一次读到半帧或多帧。超长帧丢弃到下一个 LF；CRC/UTF-8/JSON 错误不执行动作、不刷新合法帧看门狗。无法信任 `seq` 时不发带猜测 `ack_seq` 的应答，可记录本地错误；得到可信 `seq` 的完整请求才回错误 ack。帧错误本身不冒充电气故障，持续坏帧最终按通信超时处理。

### 4.1 公共字段

| 字段 | 类型 | 范围 / 含义 |
|---|---|---|
| `v` | 整数，必填 | 当前为 1；不支持的版本拒绝执行 |
| `type` | 字符串，必填 | `telemetry`、各指令名、`ack` 或 `event` |
| `seq` | 整数，必填 | 每个发送方独立自增，0–65535，65535 后回到 0；所有类型共享该发送方计数 |
| `t_ms` | 整数，必填 | 下位机上电后毫秒数，0–4294967295，约 49.7 天回绕 |

下位机生成 `t_ms`。上位机发请求时回填最近收到的下位机 `t_ms`，还未收到时填 0；该值只作关联参考，不能用作命令过期判断或心跳计时。双方超时都用本地单调时钟记录收帧时间。重连后清除旧请求关联，不跨会话重发运动；毫秒回绕用模 2^32 差值处理，设备重启时重新握手。`t_ms` 不是 Unix 时间。

### 4.2 CRC 的 C 参考实现

```c
#include <stdint.h>
#include <stddef.h>

uint16_t crc16_ccitt_false(const uint8_t *data, size_t len) {
    uint16_t crc = 0xFFFF;
    for (size_t i = 0; i < len; ++i) {
        crc ^= (uint16_t)((uint16_t)data[i] << 8);
        for (unsigned bit = 0; bit < 8; ++bit) {
            crc = (uint16_t)((crc & 0x8000)
                ? ((uint32_t)crc << 1) ^ 0x1021u
                : ((uint32_t)crc << 1));
        }
    }
    return crc;
}
```

例如初次连接的查询帧如下。CRC 已用 Python 对该行 JSON 的 UTF-8 字节实际计算；发送时在末尾追加 LF。

```text
{"v":1,"type":"get_info","seq":0,"t_ms":0}*BA73
```

## 5. 遥测（下位机 → 上位机）

`type: "telemetry"`，默认 50 Hz，每 20 ms 一帧。每帧为完整快照，不能只传变化项。安全状态变化立即补发一帧，不等待下一个周期。表内采样频率是拟定接口要求，不代表传感器已支持；温度可低频采样，但每帧携带最新值。

必填字段不可静默省略或填虚构正常值。电机离线时对应 `err` 非零，并上报 `fault`；无有效数值可将对应测量填 `null`，上位机应拒绝用它控制动作。`parseTelemetry` 遇到 J1–J3 任一 `pos_deg` 为 `null`、非数值、缺轴或 id 重复时整帧作废，不用 0 冒充读数；作废的帧不刷新显示端看门狗，持续无效时孪生转为离线。转发端仍应先做同样的校验。温度、电流等传感器的可用性及失效判据待确认。

| `v` | 整数 | 无 | 1 | 每帧 | 是 | 协议版本 |
| `type` | 字符串 | 无 | `telemetry` | 每帧 | 是 | 遥测类型 |
| `seq` | 整数 | 无 | 0–65535 | 每帧递增 | 是 | 下位机发送序号 |
| `t_ms` | 整数 | ms | 0–4294967295 | 每帧 | 是 | 下位机上电时钟 |
| `joints` | 对象数组 | 无 | 默认 6 项，id 不重复 | 50 Hz | 是 | 按 id 关联，不能按 CAN 地址猜关节号 |
| `joints[].id` | 整数 | 无 | 1–6；7 预留夹爪 | 每帧 | 是 | 显示端用 `id` 排序 |
| `joints[].pos_deg` | 数值或 null | °；id=7 时为 mm | J1–J3 见下表，其余待确认 | 50 Hz | 是 | 实测关节位置；夹爪字段名兼容约定见下文 |

### 5.1 关节坐标约定

| id | 关节 | 位置单位与约定 | 当前上位机范围 |
|---|---|---|---|
| 1 | J1 底座偏航 | °，0 ° 正对靶板；正方向与真机安装关系待确认 | −90～90 ° |
| 2 | J2 大臂仰角 | °，0 ° 水平、90 ° 竖直 | 0～110 ° |
| 3 | J3 小臂相对大臂夹角 | °，负值向下折；小臂绝对仰角为 J2+J3 | −150～0 ° |
| 4 | J4 腕俯仰 | °，按 URDF 关节轴和零位，待联调确认 | 本地 URDF 配置 −1.87～1.57 rad，仅供核对 |
| 5 | J5 腕偏摆 | °，按 URDF 关节轴和零位，待联调确认 | 本地 URDF 配置 −1.57～1.57 rad，仅供核对 |
| 6 | J6 腕旋转 | °，按 URDF 关节轴和零位，待联调确认 | 本地 URDF 配置 −3.14～3.14 rad，仅供核对 |
| 7 | 夹爪（预留） | mm，开口宽度还是单指行程待确认 | 未启用；本地 `fingerTravel: 0.0285 m` 不能直接当作开口宽度 |

J1–J3 是 `config/arm_nominal.yaml` 的软件工作范围，不是厂家机械极限。J4–J6 的 rad 数值只来自仓库 `arm-config.js` 注释所引用的 URDF 快照，没有真机验证；报文始终传 °，不能把 rad 原值直接装入 `pos_deg`。真实限位必须取工作范围与实测安全范围的交集。

当前孪生姿态只需要关节的 `id` 和 `pos_deg`，其他量用于状态/安全或附加显示。`parseTelemetry` 按 id 从 1 起连续取角度（id 7 夹爪不进角度数组），要求 J1、J2、J3 齐全且 id 唯一，否则整帧作废；不可用稀疏数组错位替代。当前孪生只用前三个角，J4–J6 仍用 `restPose`，接收 6 轴不等于已经显示 6 轴动作。

夹爪 id=7 为可选扩展，默认不发送、不下发。若双方确认纳入，沿用 `pos_deg` 字段名但以 mm 表示、`vel_dps` 以 mm/s 表示；这需要显式能力约定，不能把 mm 送进角度映射。当前驱动与孪生尚不支持夹爪。是否另用独立夹爪字段在附录 B 确认，不能由固件单方改名。

### 5.2 面板读数映射

| 面板 | 下位机 → Python → 每发记录 → 前端 |
|---|---|
| J1–J3 读数 | `joints[id=1..3].pos_deg` → `ArmState.q` → `Shot.q` → `S.recent[-1].q` |
| 负载 | `load` → `ArmState.load` → `Shot.load` → `S.recent[-1].load × 100 %` |
| 温度 | 顶层 `temp_c` → `ArmState.temperature` → `Shot.temperature` → `S.recent[-1].temperature` |
| 电压 | `vbus_v` → `ArmState.voltage` → `Shot.voltage` → `S.recent[-1].voltage` |

目前卡片只在获得新的 Shot 后更新，不是每个遥测周期更新。`config/sim.yaml` 的 `voltage: 7.4` 是仿真占位，不能当作 24 V 真机的额定电压或欠压阈值。`load` 也不能简单等同于母线电流；归一化算法必须双方确认。

## 6. 指令（上位机 → 下位机）与应答

每条请求携带公共字段，包括独立 `seq`。下位机回 `type: "ack"`，ack 自己也占用一个下位机发送序号；用 `ack_seq` 对应请求，而不是要求两个 `seq` 相同。

| 指令 `type` | 专用字段 | 执行与应答 |
|---|---|---|
| `move` | `q_deg`：有限数值数组；`speed_dps`：正数；`id`：可选整数数组 | 无 id 时固定 J1–J3，q 长度必须为 3；有 id 时逐项对应、长度相等、不重复；先验限位与速度再 ack；完成另发 move_done |
| `laser` | `on`：布尔 | false 关，true 开；安全条件满足才开；执行后 ack，并立即上报实际 `laser` |
| `estop` | 无 | 抢占正在运行的动作，关激光并锁存；返回 ack；不会自动续跑 |
| `reset_estop` | 无 | 只在急停按钮释放、故障消除、停止完成且激光已关时解除；返回 ack；不恢复旧动作或出光 |
| `get_info` | 无 | 回 ack，并在 `info` 对象中带设备资料 |
| `set_rate` | `hz`：正整数 | 设置遥测频率，默认 50 Hz；超出设备支持范围回 105，不静默裁剪；ack 带实际 `hz` |
| `heartbeat` | 无 | 每 200 ms 发送，回 ack；不改变运动状态，不引发 ack 循环 |

`speed_dps` 单位 °/s，表示每个目标轴不得超过的速度上限。当前 `task.speed` 为 30 °/s，只是请求值；真机允许上限、加减速和多轴到达策略待确认。J4–J6 只有确认坐标、零位和安全限位后才允许出现在 `id` 子集中；id=7 暂拒绝为 105，不能将角速度指令套到夹爪上。

同一时刻只接受一个 move，不排队；忙时回 203，保持已有动作。目标不可达回 202，任何参数越界先拒绝整条指令，不执行部分关节。ack `ok:true` 对 move 只表示已接受，不表示已到位。其他指令成功 ack 表示相应设置已执行，但激光物理出光状态仍须由遥测确认。

| ack 字段 | 类型 | 含义 |
|---|---|---|
| `ack_seq` | 整数 0–65535 | 对应请求的 seq |
| `ok` | 布尔 | 接受/执行是否成功，错误时 false |
| `code` | 整数 | 0 成功，非零见第 9 节 |
| `msg` | UTF-8 字符串 | 供人读的简短说明，建议不超过 80 字节；程序按 code 判断 |
| `info` | 对象，可选 | get_info 成功时必填，见下表 |
| `hz` | 整数，可选 | set_rate 成功时必填 |

| `info` 字段 | 类型 | 含义 |
|---|---|---|
| `fw` | 字符串 | 实际固件版本，不能用示例名代替 |
| `hw` | 字符串 | 下位机/臂硬件标识，命名待确认 |
| `proto` | 整数 | 支持的本协议版本，当前 1 |
| `joints` | 整数 | 转动关节数量，当前设备为 6；不含未启用夹爪 |
| `limits` | 对象数组 | 每项 `{id, min_deg, max_deg}`，已确认且允许控制的轴的安全范围；未知范围不编造 |

首次联调允许只公布 J1–J3 的已确认工作范围，即 `joints:6` 但 limits 只含 3 轴。上位机只允许控制有已确认 limits 的轴；limits 缺失的轴不可据猜测驱动。get_info 的固件、硬件标识、6 轴范围和频率能力扩展待确认。

运动完成事件为 `type:"event", name:"move_done"`，携带 `cmd_seq`（原 move 的 seq）、`ok`、`code`、`msg`。正常结束为 `ok:true,code:0`，同周期遥测 `moving:false,target_reached:true`。运动中因急停或故障终止，也必须发同一 cmd_seq 的终止结果，`ok:false`、对应错误码，`target_reached:false`；不得伪报成功。每条被接受的 move 只产生一个终态结果。

建议 ack 等待上限先设 200 ms，联调确认后固定。未收到 ack 不等于命令未执行，尤其不能换新 seq 重发 move 或开激光。需重发时仅重发同 seq、同报文字节；下位机至少保留最近 2 s 的已处理请求及应答，未结束的 move 保留到终态后 2 s。重复帧只重放已保存应答/终态，不再执行；同 seq 内容不同回 106。超时无法确认时进入停止流程，禁止继续打靶。运动完成超时依据行程、速度、加减速和稳定时间另定，不能用固定 1000 ms 限制所有动作。

| 现有接口 | 拟接入的报文与行为 |
|---|---|
| `ArmIO.move_to(q, speed)` | 发 move，等待成功 ack 和对应成功 move_done，再确认新遥测到位；异常时抛错 |
| `ArmIO.read_state()` | 从最近有效 telemetry 取 J1–J3、load、temp_c、vbus_v；过期或关键数据缺失则抛错，无独立 read_state 指令 |
| `ArmIO.laser(on)` | 发 laser，等 ack 和匹配的激光状态；失败不能更新为“已关” |
| `ArmIO.observe_spot()` | 上位机摄像头与视觉处理，不发下位机报文 |

`ArmState.direction` 是每轴接近方向，值为 −1/0/1；建议适配器在动作完成时依据运动前后实测位置计算并保留到下一动作，不把到位时的零速度当作方向。首帧无历史为 0，抗抖阈值待确认。现有 `ArmIO` 没有 estop/reset 方法，急停报文接入和真机状态合并仍需后续实现，本稿不修改接口或程序。

## 7. 心跳与超时

上位机后端独立于浏览器和打靶流程，每 200 ms 发 heartbeat。下位机收到任何合法、版本支持且公共字段有效的上位机请求就刷新本地收帧计时；CRC/JSON 错、版本不符或未知指令不刷新。已识别指令因忙、急停或参数拒绝仍说明链路有数据，但绝不能解除保护。没有收到首个合法请求前不允许动作，并从上电开始运行看门狗。

下位机连续 1000 ms 没收到合法帧：关闭激光，停止继续走向旧目标，电机保持当前位置、不掉电，锁存 `estop:true`、`estop_source:"watchdog"`、`fault:502`，`moving:false`、`target_reached:false`。遥测继续发送；若有未完成 move，发送失败终态。这里的“保持”要求供电和驱动正常，实际制动过程及失电后的防坠措施待确认；故障或实体急停的硬件关断优先。

上位机连续 1000 ms 没收到合法 telemetry：设备标为“离线”，保留最后姿态但标为过期，禁止 move、laser 开启及会触发动作的自检/标定/预检等。安全停止尝试不受该禁用约束。即使持续收到 ack，也不能代替遥测存活判据。

重连必须先 get_info 核对外层 `v` 和 `info.proto`、关节数量及允许控制轴的 limits，再确认新遥测、安全条件，最后显式 reset_estop。版本不符禁止动作；解除不自动续跑旧流程，也不自动开激光。待确认 reset 的操作人确认方式，不能仅因网络恢复自动解除。

现状：`device-source.js` 已用 1000 ms 遥测超时把孪生切到 offline，并保留最近姿态，断线后每 1000 ms 重试；它不控制主面板命令。`app.js` 主面板目前只按后端 WebSocket 连接禁用按钮，重连退避为 0.5、1、2、4、8、10 s。设备遥测超时导致后端禁令和主面板“离线”的联动尚未实现。

## 8. 安全与急停

硬件急停按钮必须直接切断电机使能与激光供电，不依赖本协议、USB、上位机进程或浏览器。软件 estop 是补充，不能承诺替代物理切断。使能切断后是否会因重力下落、是否有制动器及防坠措施待硬件同学确认。

上电默认激光关；握手前禁止动作。软件 estop 必须抢占动作，不能等 move 完成才处理。急停期间除 reset_estop、get_info、heartbeat 外，其余指令一律错误 ack、code 501；重复 estop 也按该规则拒绝，但必须保持停止和关光。laser false 同样拒绝不表示允许亮灯，急停入口本身必须已经关光并持续保持。

| 触发 | 本地处理 | 必须上报 |
|---|---|---|
| 实体按钮 | 直接切电机使能与激光供电；停止锁存 | `estop:true`、source=button、fault=501、laser=false；关断反馈异常另报 |
| 软件 estop | 终止目标运动、关光并保持停止；制动方式待确认 | `estop:true`、source=host、fault=501、moving=false、target_reached=false |
| 实际限位触发 | 停止相关运动、关光并锁存；不得继续向触发方向运动 | `limit` 对应位、相关 `joints[].err:201`、fault=201、source=fault |
| 下发目标超限 | 整条 move 拒绝，保持原状态 | ack code=201；不伪造限位传感器触发位 |
| 过温 | 停止运动、关光；是否禁能按硬件保护方案，不能无条件保持力矩 | fault=304、source=fault、temp_c；相关关节 err=304 |
| 欠压 / 过压 | 停止运动、关光，按驱动保护禁止继续输出 | fault=301/302、source=fault、vbus_v |
| 过流 | 立即触发驱动本地保护、关光、锁存 | fault=303、source=fault、ibus_a；相关关节 err=303 |
| 电机离线 / 编码器异常 / 堵转 | 停止任务并关光，保护动作由驱动能力确定 | fault=401/402/403、source=fault、对应 joints[].err |
| 通信超时 | 关光、保持当前位置、不掉电；更高优先级硬件故障除外 | fault=502、source=watchdog、estop=true，继续遥测 |

表中 source 指 `estop_source`；所有故障保护行都令 `estop:true,target_reached:false`。并发来源按 button、fault、watchdog、host 排序选择，按钮未释放不能被软件来源覆盖。整机 fault 优先报阻止安全运行的电气/电机/限位故障，其次 502，再 501；单个字段装不下全部故障时，相关关节 err 仍保留各自故障，完整多故障清单扩展待确认。

所有保护阈值、迟滞、去抖、故障复位条件和停机响应时间待确认，不从仿真温度、负载、电压或 6 mm 几何报警阈值推导。解除前须确认按钮释放、激光已关且故障消除；不能仅清掉软件标志。若无出光检测，`laser` 只能反映控制输出，这与“实际出光”的接口目标存在差异，必须在联调前明确反馈能力，不能把命令缓存当物理确认。

| 面板字段 | 下位机/适配器来源 | 当前实现边界 |
|---|---|---|
| `estop` | telemetry.estop；结合 estop_source、fault 解释停止原因；本地主动急停也先锁存 | 当前来自 Controller 的线程停止信号，尚未合并硬件遥测 |
| `laser_on` | telemetry.laser，关光请求须收到 ack 和状态确认 | 当前仅 arm.laser 调用成功后更新，不能证明物理关断 |
| `estop_error` | 后端把 fault、estop_source、失败 ack 的 code/msg、关断超时译成可读说明 | 当前只记录激光关闭失败文字，不存在同名固件字段 |

## 9. 错误码表

以下为协议草案错误码，不是厂家电机原始码。`ack.code` 表示本次指令结果，`fault` 表示整机当前故障，`joints[].err` 表示单轴故障；正常值均为 0。CRC/JSON 错无法可信关联请求时只记录错误，不构造假 ack。未知非零码按失败处理并保留原码与 msg。

| 码 | 中文含义 | 上位机处理 |
|---|---|---|
| 0 | 正常 / 成功 | 按应答类型继续；move 仍需等终态 |
| 101 | CRC 错 | 丢弃损坏帧，记录链路错误；不自动重发动作 |
| 102 | UTF-8 或 JSON 错 | 丢弃并检查编码/序列化；不执行动作 |
| 103 | 协议版本不符 | 停止控制，核对 v 和 proto |
| 104 | 未知指令 | 记录 type，核对双方支持范围 |
| 105 | 参数类型、数量或数值越界 | 修正请求，不裁剪后继续发 |
| 106 | seq 冲突或过期请求关联失效 | 停止相关流程，重建会话；不换号盲重发 |
| 107 | 帧过长或帧尾格式错误 | 丢弃到 LF，核对 1024 字节上限 |
| 201 | 超限位 / 限位触发 | 拒绝目标或停止任务，查看 limit 和各轴 err |
| 202 | 目标不可达 | 终止该动作，上位机重新求解安全目标 |
| 203 | 正忙 | 等现有 move 的终态，不排队覆盖 |
| 301 | 欠压 | 停止任务，检查供电；故障解除后人工恢复 |
| 302 | 过压 | 停止任务，检查供电/回馈；不自动重试 |
| 303 | 过流 | 停止任务，检查驱动与负载 |
| 304 | 过温 | 停止任务，检查温度来源与冷却，满足恢复条件再复位 |
| 401 | 关节/电机离线 | 检查 CAN 链路、电源及节点配置 |
| 402 | 编码器异常 | 禁止该轴运动，检修并重新确认零位 |
| 403 | 堵转 | 停止任务，排查卡滞、负载和机械干涉 |
| 501 | 急停中 / 不满足解除条件 | 保持禁令，显示来源与拒绝原因 |
| 502 | 看门狗通信超时 | 标离线/停止，重连握手并显式解除 |

H1、H2、H3、H4、H5、H6 是上位机几何诊断假设，不属于上述电气/通信错误码，不能由固件填进 `fault`。

### A.3 Shot 与几何参数字段

`Shot` 完整字段如下。前三轴位置、环境量来自下位机；其余由上位机产生。`direction`、`uncertainty`、`anomalous` 虽未直接画出，也不能误写成必需的固件诊断结果。

| 字段 | 页面使用 / 含义 | 数据来源 |
|---|---|---|
| `timestamp` | 误差图提示和 panel 孪生帧时间，Unix 秒 | Shooter 在发次结束时 `time.time()`，不是 t_ms |
| `q` | 三轴角度、孪生姿态，° | 下位机 joints[id=1..3].pos_deg，经 ArmState |
| `direction` | 接近方向，未直接展示 | 上位机适配器依据相邻实测位置计算，−1/0/1 |
| `load` | 负载百分比 | 下位机 load |
| `temperature` | 温度，°C | 下位机顶层 temp_c |
| `voltage` | 电压，V | 下位机 vbus_v |
| `predicted` | 预测二维落点，mm | 上位机几何与补偿模型 |
| `observed` | 实测二维落点，mm；丢失为 null | 摄像头（接上位机）与视觉识别 |
| `residual` | observed−predicted，二维 mm；丢失为 null | 上位机计算，面板显示其模长 |
| `uncertainty` | 二维预测标准差，当前未直接展示 | 上位机补偿模型 |
| `version_id` | 图中版本线和提示 | 上位机发次所用版本 |
| `anomalous` | 训练过滤标记，当前未直接展示 | 上位机异常检测/流程标记 |
| `role` | 常规、标定拟合、标定验证、认旧探测、诊断、主动诊断、护栏验证、预检 | 上位机；值为 task/baseline_fit/baseline_holdout/recognition/diagnostic/active_diagnostic/guard/preview |

预检内的行另有 `q`、`observed`、`candidate`、`current`、`candidate_mm`、`current_mm`；页面只显示两个误差值和序号，其他坐标由上位机保留。preview 的 `time` 用于后端有效期检查，页面不直接显示。当前 `Controller.preview()` 将试打写入日志但不发 shot 事件、不加入 recent 或累计 shots，不能声称预检逐发更新主图和关节卡片。

版本参数 `params[k]`、诊断 `deltas[k]`、`gear_steps[k]`、候选 `fit.free[]` 的标签映射如下，全为上位机模型参数，不经下位机：

| 字段 | 参数 | 单位 |
|---|---|---|
| `delta1` | J1 零点偏移 | ° |
| `delta2` | J2 零点偏移 | ° |
| `delta3` | J3 零点偏移 | ° |
| `h` | 肩高 | mm |
| `L1` | 大臂长度 | mm |
| `L2` | 小臂长度 | mm |
| `e` | 延长长度 | mm |
| `beta` | 激光俯仰 | ° |
| `gamma` | 激光偏摆 | ° |
| `x_b` | 底座 X 平移 | mm |
| `y_b` | 底座 Y 平移 | mm |
| `psi_b` | 底座朝向 | ° |

### A.4 上位机事件 kind 对照表

事件统一封装为 `kind`、`timestamp`、`data`；服务端首次连接直接生成的 snapshot 没有 timestamp，前端不靠它显示事件时间。下表覆盖 Controller 的所有 emit/publish 类型，以及版本库补充类型。固件不需要生成这些 kind，固件 move_done 等由未来适配器消费。

| `kind` | payload 字段 | 前端用途与来源 |
|---|---|---|
| `snapshot` | `data.snapshot` | 覆盖 S；上位机快照，并由 server 保留静态配置和实时安全状态 |
| `state` | `data.state/heal_start` | 更新状态芯片与自愈进度；上位机状态机 |
| `operation` | `data.busy/active_command` | 更新按钮状态；上位机流程 |
| `laser` | `data.laser_on` | 更新激光芯片和默认孪生；当前软件调用结果 |
| `estop` | `data.estop/laser_on/estop_error` | 横幅、禁止动作、最近事件；当前上位机锁存 |
| `safety` | `data.estop/laser_on/estop_error` | 更新关光结果与急停错误；当前上位机安全处理 |
| `estop_reset` | `data.estop/laser_on/estop_error` | 清横幅、最近事件；上位机解除流程 |
| `shot` | `data.shot`，全部字段见 A.3 | 更新 recent/shots、相机和图；上位机合成 |
| `alarm` | `data.count` | 最近事件；上位机异常检测 |
| `switch` | `data.version_id/rms/probe_shots` | 识旧事件；rms 不在事件文字展示；上位机识旧 |
| `diagnosis` | `data.diagnosis` | 更新诊断卡片；上位机拟合 |
| `calibration` | `data.mode/result`，mode 为 baseline/recovery | 后端会发布，app.js 当前忽略；上位机校准 |
| `preview` | `data.preview` | 版本预检表；上位机比较两套模型 |
| `retrained` | `data.report/accepted` | 最近事件读 accepted，报告随版本/快照保存；上位机训练 |
| `manual_switch` | `data.from/to/time/operator/undo/forced` | 事件文字读 from/to/undo/forced；上位机版本切换 |
| `damage_injected` | `data.damage.kind/amount/components` | 事件文字读 kind/amount；components 递归组合供后端使用，页面不展开 |
| `version_committed` | `data.version_id/meta` | 最近事件；版本库发布，不由 Controller 直接发布 |
| `rejected` | `data.version_id/reasons` | 最近事件只读 id，原因在版本详情；版本库发布 |
| `rollback` | `data.from/to/component` | 收入 events 但最近事件过滤；版本库发布 |

`handle()` 对 state/operation/estop/estop_reset/safety/laser 会合并整个 data，因此不能直接把同名固件消息塞入前端事件。`rearm:state` 是浏览器本地 CustomEvent，detail 为 `{state:S, connected}`，供 panel-source 使用，不是固件报文；`rearm:modules-ready` 和 `rearm:theme` 也是本地通知。

## 附录 C：二进制帧布局建议

只作资源受限时的备选，不属于本版串口互通要求。先约定新的承载模式再启用，不在 JSON 链路里自动探测切换。

| 顺序 | 布局建议 |
|---|---|
| 帧头 | 固定同步字 2 字节、payload 长度 uint16、v uint8、type uint8、seq uint16、t_ms uint32 |
| 遥测 payload | 关节数 uint8；逐轴 id uint8、位置/速度/转矩/温度各 float32、err uint16；随后状态位、source uint8、limit uint8、电压/电流/负载/总温度各 float32、fault uint16 |
| 其他 payload | 按第 6 节同名字段定长/长度前缀编码，保留 ack_seq、cmd_seq、ok、code 和 UTF-8 msg |
| 帧尾 | CRC16/CCITT-FALSE uint16，建议覆盖 v 至 payload 末字节 |

整数/float32 建议统一小端，数值单位沿用 JSON；缺测另设有效位图，不用 0 冒充。状态位至少覆盖 moving、target_reached、laser、estop、sim；类型、来源枚举值、有效位图和长度范围待确认。此布局经解码后应还原同一逻辑 JSON 对象，不能把二进制帧直接传给当前 `device-source.js`。
