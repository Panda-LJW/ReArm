# B601-DM 末端轨迹换算调研

核查日期：2026-11-14。仅阅读源码并做离线数学试算，未连接机械臂、电机、串口或相机。

## 1. 一句话结论

**已有现成换算，ReArm 面板建议保留现有 kinematics.js 的六轴 FK，以官方 Pinocchio SDK 的 DM 模型作独立对照；接入真机轨迹前须补齐六轴零位/方向以及工具、相机外参。** 当前三轴面板映射不能直接套六轴电机读数，七组数值对照见第 4 节。[本地 FK][L-FK]、[映射配置][L-CONFIG]、[官方 FK][S-FK]

## 3. 输入、输出约定

### 3.1 关节角、零位与正方向

输入顺序是 joint1…joint6，单位 rad。第 7 个夹爪电机不是第 7 个机械臂转动关节。Pinocchio DM 模型还包含左右两个滑动指；q 长度按 model.nq，本轮为 8，算 end_link 时前六项填角度，双指填 0。[URDF][J-URDF]、[SDK 模型工具][S-MODEL]

| 关节 | URDF 局部 axis | URDF 限位 rad | 零位轴在 base_link 中的近似方向 |
|---|---|---|---|
| J1 | (0,0,1) | [-2.8,2.8] | +Z |
| J2 | (0,0,-1) | [-3.14,0] | −Y |
| J3 | (0,0,1) | [-3.14,0] | +Y |
| J4 | (0,0,1) | [-1.87,1.57] | +Y |
| J5 | (0,0,1) | [-1.57,1.57] | −Z |
| J6 | (0,0,1) | [-3.14,3.14] | +X |

正方向按对应轴的右手定则，近似方向由固定旋转算出，保留 URDF 中 1.5708 的精度。q=0 是模型零构型，不是面板“大臂水平角”，也不是任意上电位置。**J2 的负轴已写入 URDF，也已包含在 DH 推导中，不能再把 DH 输入 q2 额外取反。**[URDF][J-URDF]、[DH 源码][J-FK]

机械零位需要按实际装配校准。LeRobot 的 calibrate 要人工摆默认坐姿并闭合夹爪后写电机零点；joycon 当前示例同样依赖硬件零位。它们不是从未知姿态自动求零偏的程序。本轮未证实用户这台的电机 Flash 零点与模型一致，也没有运行任何校零程序。[LeRobot calibrate][L-FOLLOWER]、[joycon 校零类][J-CAL]

### 3.2 电机原始读数到关节角

| 来源 | 现成代码怎样转换 | 限制 |
|---|---|---|
| joycon examples/Motor_CAN.py | 将反馈字节 1、2 拼 16-bit 位置，线性解码为 rad | 默认位置量程 ±12.5 rad |
| MotorBridge 达妙 protocol.rs | decode_sensor_feedback 解包，motor.rs 给型号量程 | 4310、4340P 默认 ±12.5 rad |
| 官方 SDK JointGroup.get_positions / RebotArm.get_state | 直接用 MotorBridge state.pos 形成 rad 数组 | 无额外 sign/offset/减速比；部分缺反馈分支补 0 |
| joycon 当前 examples 的 ReBotCalibration | IDs 1–7，sign 全 +1、offset 全 0 | 依赖已经正确设置的电机硬件零点 |
| joycon 内嵌 LeRobot 的旧标定类 | q = sign × (motor_rad − offset_rad) | 读 JSON 和 .encoders.json，不能重复扣零偏 |
| 上游 LeRobot _present_pos | degrees(state.pos) / joint_direction | DM 方向全 +1；公开 .pos 是度，FK 前要转 rad |

源码：[Motor_CAN][J-CAN]、[MotorBridge protocol][B-PROTOCOL] / [型号参数][B-MOTOR]、[官方读取][S-ACTUATOR]、[当前标定][J-CAL] / [旧标定][J-LEROBOT-FK]、[上游读数][L-FOLLOWER] / [DM 方向][L-MOTOR]。

默认达妙反馈的公式是：

**motor_rad = raw16 / 65535 × 25 − 12.5**

这是 CAN 协议的量化角度字段，不是“物理编码器一圈 65536 线”的证据。上述读取链没有再除减速比，也没找到原始 CPR、独立圈数与跨圈拼接的 B601 换算代码。因此对 MotorBridge pos 或 SDK 已解码角度，不应自行再除减速比；位置量程仍须与电机实际设置一致。[解码][B-PROTOCOL]、[参数表][B-MOTOR]、[SDK][S-ACTUATOR]

如果下位机将来传物理编码器计数，还需确认：读数来自电机轴还是输出轴、每圈分辨率、减速比、圈数表达和断电恢复方式。**没找到可不核验这些参数就直接套本机的“原始编码器计数 → 关节角”程序；已找到的是“协议角 rad → 校零后的关节角 → FK”。** 上述 SDK/驱动代码中没有提供这些缺失量。

### 3.3 坐标系与“末端”的定义

同模型对照均在固定 base_link 下，长度 m。J1 原点位于 base_link 的 (−0.00008416,0,0.08465) m，即 base 原点在 J1 原点下方 84.65 mm、X 相差 0.08416 mm。模型 Z 向上，零位机械臂主要向 +X 延伸，+Y 由右手系确定；与实体桌面、靶板、世界原点的关系仍需测量。没找到足以把 base_link 原点严格认定为用户底板某个实测孔心的证据。[URDF][J-URDF]、[本地配置][L-CONFIG]

| 输出 | 定义 | 能否当实物指尖/相机 |
|---|---|---|
| frames.joint6 / link6 | 第六关节转动后的连杆系 | 实体法兰基准是否重合没验证 |
| ReArm tool / SDK end_link | link6 后平移 (0,0,0.15539) m，RPY=(0,−1.5708,3.1415) | 固定工具参考系，不自动等于夹持中心或矩形指尖 |
| joycon DH / MuJoCo tcp | end_link 局部 X 再偏 −0.105 m，旋转不变 | 旧模型约定点；不等于当前自制指尖 |
| 新 MoveIt gripper_tcp | 新 gripper_link 局部 X 再偏 −0.0443 m | 还改了腕部尺寸和固定旋转，不能直接混比 |
| Yang-Ci 网页 getTcpPosition | 实际取 end_link，必要时回退 link6 | 网页名称 TCP 不等于其 MuJoCo tcp |

出处：[URDF][J-URDF]、[模型 README][J-MODEL-README]、[MoveIt Xacro][R-XACRO]、[网页源码][Y-WEB]。模型 README 明确写了：100 mm 指爪替换后 end_link / tcp 没重定义，tcp 不是新指尖。

本报告用 T_base_tool 表示把工具系点变到基座系：p_base = R_base_tool · p_tool + t_base_tool。SDK data.oMf 与本地矩阵按此解释；SDK docstring 的“从世界系到该帧”容易读反，以代码和此点变换式为准。本地数组是行主序，平移在索引 3、7、11。[SDK FK][S-FK]、[本地 FK][L-FK]

建议保存 4×4 或位置+四元数。joycon rebot_FK 的欧拉角辅助运算舍入到小数点后 3 位；位置未舍入，但相机姿态宜直接用 robot.fkine(q).A，避免从其 RPY 反推。[J-FK]

官方 SDK 当前 config/rebotarm.yaml 默认选择 **RS**，无参数 joint_to_pose 可能加载错机型；应显式选 DM URDF 和 end_link。SDK 声明 Python ≥3.10、<3.12；本轮仅在临时 Python 3.12 中调用纯数学函数，不表示完整 SDK 安装兼容性已验证。[默认配置][S-DEFAULT]、[DM 配置][S-DM]、[pyproject][S-PYPROJECT]

### 4.5 真实接入的差异

把六轴 URDF 角转成度后误送现有 panelToUrdf，全零样本会偏 **536.328 mm**，七组最大偏 **1065.994 mm**：前三轴被套用原三自由度靶板映射，后三轴又被 restPose 替代。这是坐标约定误用演示，不表示当前三轴面板逻辑自身算错。[结果][T-BASE-RESULT]、[映射][L-CONFIG]

当前 twin.js 按 panelMapping 长度截取前三轴，还以 0.18 系数向目标平滑靠拢；实际轨迹应取原始有效测量帧，不能从动画 shown 数组采样。forward 也会把缺失/NaN 当 0、把越界角夹到限位，后续轨迹入口应先校验完整六轴，不静默修饰测量。[twin.js][L-TWIN]、[FK][L-FK]

我们仍需补的数据：

| 项目 | 应确认/测量什么 |
|---|---|
| 安装对象 | 相机型号、支架版本，装在固定夹爪骨架还是活动指/滑块 |
| 工具参考点 | link6、end_link、夹持中心或哪个指尖；自制夹指尺寸和安装面位置 |
| 相机外参 | 相对所选工具系的 tx、ty、tz 和完整三维旋转，注明 m/rad、方向 |
| 光学系 | 外参指向 RGB、depth 还是机壳；必要时补厂商 RGB/depth 内外参 |
| 标定与同步 | 实际相机内参/畸变、标定板尺寸、图像与六轴反馈时间对应、独立姿态复验 |

工程推导：固定在夹爪本体时，T_base_camera(t) = T_base_tool(q(t)) · T_tool_camera；若相机装在活动指或滑块上，还需乘夹爪开度相关变换，六个机械臂角独自不足。旧 URDF 双指沿局部 Y 反向滑动，但不能据此猜自制夹指和相机安装值。[finger joints][J-URDF]、[手眼求解][H-SOLVE]、[本地实物资料核查][L-PACKAGE]

只画相机光心路径时，固定外参的平移与工具姿态可求位置；要显示相机姿态或把深度点变到基座系，还需完整光学旋转。以上均未实机标定。

| 工具 | 已有功能 | 还缺什么 |
|---|---|---|
| joycon examples/runtime_log.py + ReBot_SDK.py | JSONL 的 feedback 记录七路位置、速度、力矩和各电机反馈时间 | 筛有效六轴，按时间对齐再 FK；没找到专用末端 CSV 导出器 |

| Yang-Ci rebot-sim.js 示教 | 录点、真机采样、JSON 导入导出、回放 | 网页点有 tcp_ros，真机原始样本只有 q 和时间，仍需逐点 FK |
| ROS2 workspace | JointState、FollowJointTrajectory、MoveToPose 接口 | 已读源码没找到完整“反馈录制 → 末端 CSV”工具 |

Yang-Ci 导出的 positions 是 rad，frame_id=base_link，有 time_from_start；raw 真机格式为 rebotarm_dm_teach_v1，网页格式为 rebotarm_ros_waypoints_v1。raw 样本没有计算 tcp_ros，JSON 中会省略；网页所称 TCP 又是旧 end_link 原点。因此不能称为“已直接导出我们的夹指尖/相机轨迹”。[Y-WEB]

官方 SDK 另有 trajectory/trajectory_planner.py::compute_traj_stats，对规划关节序列逐点调用 FK，可参考其遍历方式；它不是反馈录制工具。example/sim/traj_sim.py 是规划轨迹的 MeshCat 展示。[SDK 轨迹工具][S-TRAJ]

## 7. 对 ReArm 的建议（只建议，未修改）

1. **保留现有 FK 连乘和六轴几何。** 数值已与官方 DM 模型对上。浏览器画轨迹无需为了 FK 引入 ROS2 或 Python；后端可用官方 compute_fk 独立核对。[第 4 节结果][T-RESULT]
2. **单独定义六轴实测入口。** motor_rad 经实测 sign/zero 转成 joint1…joint6 的 URDF rad，绕过三轴 panelToUrdf/restPose。已由 SDK/LeRobot 转好方向和零位的数据不重复转换。device-source 当前最低接受三轴，twin 又截前三轴，后续接入需要连同这些边界一起明确，不能只改 FK。[配置][L-CONFIG]、[遥测][L-DEVICE]、[孪生入口][L-TWIN]
3. **分开末端命名与安装变换。** 把现有 tool 明确叫 end_link，另保存 T_end_tcp、T_end_camera。−105 mm 仅用于复现旧模型；矩形指和相机用实测值，固定变换右乘，不在世界 X 直接减 105 mm。[模型定义][J-MODEL-README]、[对照结果][T-RESULT]
4. **按测量时间记录真实轨迹。** 保留原始六轴 q、时间、有效性/各轴反馈时间、标定版本；缺轴、越界、断线标记并断开轨迹，不补零或悄悄夹到限位。动画平滑不参与采样。device t_ms 是上电时间，JointFrame 注释却写 Unix 时间，后续需统一时钟域。[FK][L-FK]、[twin][L-TWIN]、[接口文档][L-PROTOCOL]、[frame.js][L-FRAME]
5. **校准后再谈实物精度。** 核对零位/方向、模型版本和工具/相机外参，再做独立实测姿态验证。关节角重建的是模型预测轨迹，不能观测所有柔性形变或齿隙。0.20 m 安装台是显示布置，不应加进 base_link 的 FK。[决策日志][L-DECISIONS]、[scene.js][L-SCENE]

当前三自由度自我模型与 B601 孪生用途不同；是否统一属于另一项设计任务，本轮不建议顺手替换核心模型。[决策日志 D2][L-DECISIONS]
