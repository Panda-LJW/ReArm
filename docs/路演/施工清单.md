## 2. 生产

### 2.1 配方

工作区里放着一个工装和若干零件，**位置随意**。例子：
- 工装：一个圆盘，上面立着一根定位柱，定位柱就是基准点
- 右边放一块薄片，中间有孔
- 左边放一个空心圆柱

配方“薄片 + 空心圆柱配套件”：先把薄片套进定位柱，再把空心圆柱套进去。

### 2.2 流程

**选配方 → 开始 → 二次确认 → 自检 → 起身到观察位 → 识别 → 抓取 → 放置 → 抓取 → 放置 → 检查 → 完成 → 收回折叠状态**

- **二次确认**：弹窗“确认工作区附近无人”，勾选后才能确认。
- **自检**：状态显示“自检中…”，逐项打勾：通信、6 个关节、夹爪、深度相机。
- **起身到观察位**：机械臂从折叠状态起身，沿预先录好的固定轨迹走到观察位，相机垂直对着工作台面。这条轨迹只录一次，所有配方共用。
- **识别**：在观察位一次认出工装、定位柱和配方里的每个零件，在画面里框出来，标上名称和置信度。
- **抓取 / 放置**：按配方顺序，每个零件抓一次、放一次。夹爪全开；J6 按视觉结果实时对准，识别到的角度只在这一刻显示，不存档；夹持力用零件文档里的值。
- **检查**：全部放完后回到观察位拍一张，确认装配到位，给出“到位”或“偏差 x.x mm”。这一步是演示重点。
- **完成**：计入完成套数和一次通过率，然后沿固定轨迹收回到折叠状态。

### 2.3 首屏

首屏极简，只留：大的数字孪生、当前状态、一个关键数字和它的趋势、主按钮、急停。配方步骤的进度用一行小字或一列简单的步骤显示，其他信息都收到次要位置。

## 3. 零件库

### 3.1 零件：新增三步

流程栏放在建档页左侧，每一步的按钮只在这一步出现。

| 步骤 | 按钮 | 做什么 |
|---|---|---|
| 1 识别零件 | 拍照识别 | 在观察位拍照，得出轮廓和尺寸，确认名称和编号 |
| 2 训练 | 开始训练 | 机械臂基本停在观察位看，偶尔在一个竖直平面内换几个角度观察，并试着抓取。训练什么时候结束不用人点，到时自动停 |
| 3 入库 | （自动） | 训练完成即收录，生成零件文档 |

训练过程中显示：第几轮、每一轮的偏差（mm，逐轮下降的曲线）、试抓成功或失败、已观察的图像数、用时。结束时显示“训练完成 · 已收录”。

### 3.2 零件文档

- 外形照片、轮廓和尺寸
- 夹持力：模拟数据，每个零件在 12 N 上下（相差不到 1 N），附估算依据（估计重量、材质、摩擦系数、安全系数）
- 开口：全开
- 训练记录：逐轮偏差曲线和阈值线、试抓记录、图像数、用时
- 训练录像：入口放在训练记录里，点开就播放（见 3.5）
- 收录时间、版本
- “重新训练”按钮

**不写进文档**：夹取角度（每次由视觉实时判断）；运动轨迹（固定轨迹是共用的，抓取和放置的动作由模型现场决定）。

### 3.3 配方

- **配方文档**：名称、工装、装配顺序（每一步用哪个零件、放到哪里）、用到的零件（链接到各自的零件文档）、装配训练记录（逐轮偏差曲线、成功率）、收录时间、版本。
- **新增配方**：选工装和零件、排好顺序 → 装配训练 → 入库。流程栏和新增零件一样。

### 3.4 现场不演示训练

原因有三：训练时间长；人来人往、光线变化大，影响训练；训练所用的技术是企业机密。

对外口径统一为“模型自己识别”。新增零件、新增配方的流程照样做完整，按钮能点，不出现“待开发”，但现场不主动去点。评委问到训练是什么样子，就放训练录像。

### 3.5 训练录像

原始素材是手机拍的，约 1 小时，只拍了机械臂和工作区，中间有大段空白。处理要求：
- 剪掉空白段，倍速播放
- **音轨全部去掉**：录到了现场对话

成片有两个用途：一是放进零件文档，第一轮现场随时能点开；二是作为第二轮视频的素材。素材目前还在手机里，模型还在训练，导出后再处理。本机已经装了 ffmpeg。

### 3.6 模拟数据

- 零件：4 个，已收录。薄片、空心圆柱，另外两个待定。每个零件和工装都有 3D 模型，之后提供：零件文档的外形图和数字孪生里的零件都用这些模型
- 配方：“薄片 + 空心圆柱配套件”，已收录

## 4. 措辞规则

- 不出现“模拟”字样。
- 只说“模型”，不出现教师模型或它的名字；对外口径是“模型自己识别”。
- 状态用短词：待命、自检中、就绪、识别中、抓取中、放置中、检查中、完成、训练中、急停。
- 训练结束写“训练完成”。“收敛”只用在曲线注释或讲解里，用来回答“为什么停在这里”。

## 5. 现有成果怎么处理

- **偏差曲线**：搬进零件文档和配方文档的训练记录。
- **阈值圈、示范 / 练习按钮、激光手动开关、激光守护**：从界面上撤掉，面板不再发任何激光指令。代码保留，不加载；`?legacy=1` 仍能打开旧首页。
- **数字孪生、6 轴参数、夹爪模型**：照用。
- **接口文档需要补**：开机、自检、固定轨迹走到观察位、识别结果（多个目标的框、名称、置信度、角度）、抓取和放置步骤、装配检查结果、训练进度（轮次、偏差、试抓）、训练完成、零件文档、配方文档。另一台主机目前没有这些，前端先用模拟数据。

## 6. 控制台的范围

这是 42 小时黑客松的演示，范围按“评委一两分钟内看得到”来砍。

## 8. 给执行者

**分工（省 Fable 额度）**：
- **Codex**：写代码，跑验收脚本，按脚本结果自己返工，直到全部通过。
- **验收脚本**：由 Fable 或 Codex 写都可以，用的额度不多。谁写都必须严格照第 9 节的标准，不能为了让代码通过去放宽标准。
- **Fable**：只在三种情况介入：开工时把任务拆好、交给 Codex；同一项验收连续两次修不好；遇到需要选路线的问题。平时不逐项盯。
- **用户**：每个节点最后看验收报告，并亲手过一遍。

**节点规则**：每个节点的第一件事，是按第 9 节写好这个节点的验收脚本（Fable 或 Codex 写）。做完以后跑一遍，全部通过才生成验收报告交给用户：报告里有启动方式、逐条结果、截图、改了什么、哪些没做。用户明确说通过之前，不开始下一个节点。

- **代码在哪**：前端在 `rearm/ui/static/`，没有构建步骤，原生 ES 模块。可选模块由 `modules/main.js` 加载，单个模块出错不能拖垮整页。现有的训练模块在 `modules/trainer/`，孪生在 `modules/twin/`，机械臂参数和运动学在 `modules/arm/`，模拟主机在 `modules/datasource/mock-host.js`。
- **设计依据**：本清单；品牌规范 `/static/brand.html`；旧版设计 `docs/model-swap/设计.md`；接口文档 `docs/接口文档.md`（要按第 5 节补充）。
- **启动**：`.venv/bin/python -m rearm.ui.server --sim --nongeometric --data-dir runtime/panel-demo`，打开 `http://127.0.0.1:8000/`。
- **测试**：`.venv/bin/python -m pytest -q`，目前 324 个全部通过，不能变少。
- **页面验收**：见第 9 节，用 Playwright 加无头 chromium。
- **红线**：
  - 不合并到 main，不改写已有提交历史，不删分支；每一项单独提交
  - 不连接、不驱动真实机械臂、相机或另一台主机，只用模拟数据；前端代码里不写死任何真机地址
  - 急停、限位、安全相关的行为不改，只能新增展示
  - 不安装全局软件，不往项目的 `.venv` 里装包
  - 仓库根目录的 `海报素材包.zip` 不是我们的，永远不要提交
- **开工前**：仓库根目录有 `docs/goal_轨迹训练前端.md`，那是上一阶段的目标。和本清单冲突的地方（首页做成示范 / 练习、激光守护等），一律以本清单为准。

## 9. 节点①（控制台）验收脚本

### 9.1 怎么跑

- 一条命令：`scripts/acceptance/node1.sh`。它会先跑 pytest，再起一个临时服务（端口 8031，跑完关掉），然后用 Playwright 驱动无头 chromium 按 9.3 逐条检查。
- Playwright 用 `~/.npm/_npx/*/node_modules/playwright-core`；浏览器用 `~/Library/Caches/ms-playwright/chromium_headless_shell-*/*/chrome-headless-shell`。不装任何新东西。
- 输出：
  - `docs/路演/验收/节点1/报告.md`：每条一行，写明通过或失败、实测值、对应截图
  - `docs/路演/验收/节点1/screenshots/`
  - 全部通过时退出码为 0，并用 `open` 打开报告

### 9.2 页面上要留的钩子

脚本靠这些属性找元素，实现时必须带上：

| 钩子 | 放在哪 |
|---|---|
| `[data-nav="production|parts|records|settings"]` | 四个导航项 |
| `[data-page="..."]` | 四个页面的根元素，取值同上 |
| `[data-status]` | 状态标签，文字就是当前状态 |
| `[data-action="start|confirm|reset|estop"]` | 开始、确认、一键重置、急停 |
| `[data-confirm-check]` | 二次确认弹窗里的勾选框 |
| `[data-recipe]` | 配方选项 |
| `[data-part]`、`[data-recipe-doc]` | 零件库里的零件和配方条目 |
| `[data-new-flow]`、`[data-step]` | 新增流程和其中的每一步 |
| `[data-twin-label]` | 孪生里的关节和节点标签 |
| `window.__rearmMock.commands` | 模拟主机收到的指令记录（数组） |
