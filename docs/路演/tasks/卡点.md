# 节点① T0 卡点

## 2026-11-15：第 16 条与现有受保护代码冲突

任务书要求扫描全部 JS 中的 IPv4 和 URL 主机名，仅允许 localhost、127.0.0.1，只有 vendor 例外。现有 `rearm/ui/static/modules/trainer/views/camera.js:34` 含 `http://www.w3.org/2000/svg`；`modules/datasource/index.js:17` 和 `device-source.js:2` 含地址示例。

因此严格扫描无法使第 16 条转绿。SVG 命名空间不是网络连接，但任务书没有允许该例外；同时 A.2 禁止修改旧训练模块。本轮保留这些命中，不改产品代码、不增加白名单、不提交。

## 2026-11-15：验收脚本首次执行前自审

以下是新脚本草稿的实现缺口，先记录原因再修正，判断标准不变：

- 服务就绪探测只用 HTTP 200 可能误连端口上原有服务。改为等待本次服务日志的监听成功标记，同时核对本次子进程仍存活；端口固定 8031。
- 第 9 条须覆盖所有可见的不可用按钮，不能只测确认按钮。提取通用悬停测量，并用于四页、文档和新增流程。
- 第 11 条不能把宽度或高度为零的 SVG 线条全部排除，否则可能漏掉可见的红色描边。

上述修正均发生在首次运行前，不是失败后放宽验收；本轮未对同一项连续进行两次产品修复。

## 2026-11-15：第 16 条的裁定（Fable）

第 16 条的目的是“前端不写死真机地址”。三处命中都不是地址：`camera.js:34` 是 SVG 命名空间标识符（`createElementNS` 必须写，浏览器不会连接它）；`device-source.js:2`、`index.js:17` 是注释里的占位写法（`ws://…`、`ws://主机:端口`），不是合法主机名。

裁定：脚本只对这两类不计失败，条件写死为“逐字等于 W3C 的两个命名空间字符串”和“主机部分不是合法主机名”，每次命中都在报告第 16 行逐条列出。其余任何合法主机名或 IP（包括 `www.w3.org` 出现在别的写法里）照样判失败。这一条需要用户在验收时过目。
