# 节点④设备层与后端接入任务书

把控制台接到真实机械臂主机，完成一套配方的自检、识别、抓取、装配、检查和收回。硬件参数、测量结果与任务状态以主机为准，前端只负责显示和业务操作。

M13 明确写了“失能后电机不出力，手臂会在重力下落下”；因此不能把模拟器的“急停后原姿态冻结”当成真机承诺。M13 的职责主要是驱动，本任务书补它上面的业务与协议层，不重写 CAN 协议。

## 3. D0：先固定契约

真实控制台采用 **v2 协议**，旧训练与模拟 v1 保留。原因是位置有效性、缺测、错误终态和急停恢复的含义需要变更，不能仍标 v1 却悄悄改变语义。

新增独立文档 `docs/接口-控制台真机-v2.md`，不覆盖正在施工的 `docs/接口文档.md`。用同一组 JSON Schema 和样例验证主机输出与前端输入；只验证报文，不运行设备动作。

| 端点 | 用途 |
|---|---|
| `POST /api/v2/command` | 接受业务命令，返回请求和任务 ID |
| `WS /api/v2/events` | hello、状态、遥测、事件、心跳 |
| `GET /api/v2/snapshot` | 当前任务、库版本、统计及事件水位 |
| `GET /api/v2/commands/{request_id}` | 查询超时或断线后的执行结果 |
| `GET /api/v2/runs`、`GET /api/v2/trains` | 分页恢复持久化记录 |

指令信封统一 `v:2、cmd、request_id、seq、t`，业务参数仍放顶层。应答统一 `v、request_id、seq、accepted、code、msg、run_id/train_id`；无关联任务的 ID 为 null。`accepted:true` 只表示接受，业务结果由任务事件给出。

推送统一 `v:2、type、session_id、seq、t`。session_id 每次主机进程启动改变，seq 在该 session 内单调递增，t 为 Unix 毫秒。运行、训练、请求、物体实例各有独立 ID；零件类型 ID 不能代替画面中的物体实例 ID。

业务任务采用两个独立字段：`phase` 沿用 selfcheck、recognize、pick、place、inspect、to_fold 等工序；`status` 为 running、succeeded、failed、cancelled、estopped。错误不冒充 idle，未确认设备状态时不得开放开始按钮。

前端数据源先校验各自的线上版本，再转换为内部事件；不能把 v2 报文的版本号改成 1 来绕过校验。store 和页面增加缺测、失败及真机恢复显示，这是节点④所需的小范围改动，不能承诺仅改地址就完成接入。

**验收：**同一批样例在双方通过，包含成功、失败、null、重复、迟到、主机重启和未知版本；不支持的版本拒绝业务操作。

## 4. D1：硬件参数冲突的解决办法

### 4.1 主机发布一份设备配置

由主机根据已加载的驱动、几何和标定配置生成 `device_profile`，通过 hello 返回 `profile_id/revision` 和配置读取地址。前端按 profile 建立显示参数；模拟仍使用自己的配置。前端不能修改驱动限位。

| 字段组 | 内容 | 来源 |
|---|---|---|
| 身份 | device_id、profile_id、revision、geometry_model_id | 主机设备配置 |
| 关节 | 顺序、单位、已批准运行范围、命令余量 | 实际加载的 Driver6Config |
| 变换 | `T_base_end` 定义、`T_end_tcp`、`T_end_camera` | 几何模型与实机标定 |
| 夹爪 | 最大开口、换算方法、有效标定 ID | 当前夹具实测与当次参考 |
| 版本 | 模型、标定、工装和固定轨迹版本 | 主机有效配置 |

矩阵统一 4×4 行主序，平移单位 mm，旋转无单位；变换名 `T_A_B` 表示把 B 系坐标变到 A 系。前端进入 Three.js 时才把长度转成 m。完整矩阵须校验有限值、齐次末行和合法旋转，不能只换三个坐标数。

### 4.2 逐项处理已有冲突

| 冲突 | 实施办法 | 通过条件 |
|---|---|---|
| TCP 相差 105.5 mm | 以 end_link 作共同参考，另标定实际两指接触中心的 T_end_tcp | 同姿态、同参考点对照一致 |
| 夹爪 110 mm | 真机与模拟统一为 110 mm（2026-11-15） | 当次力矩标定换算；无有效参考时显示缺测 |
| J4 工作位越界 | 显示使用主机已批准范围；运动仍用驱动检查 | 1.89155 rad 正确显示，不新增放宽 |
| J2/J3 停放位差异 | 同样读取实际驱动范围与命令余量 | 不套用旧 URDF 范围否定真实反馈 |
| 7 路与 6 路 | 前 6 路为机械臂，J7 单独表示夹爪 | 六轴 FK 不收到 7 元数组 |
| 力矩与电流 | `torque_nm` 和 `current_a` 分开 | 无电流传感数据时 current_a 为 null |
| 温度含义 | 保留 mos_temp_c、rotor_temp_c | 页面说明显示的是哪种温度 |

TCP 的处理不是把全局坐标固定平移 105.5 mm。这个差值随末端朝向旋转，必须通过 `T_base_end × T_end_tcp` 求取。保留上游 `kin6` 的默认 TCP 参数供原算法使用，给新夹具建立独立 profile，避免改坏旧算法和历史数据。

夹爪使用当前力矩寻端建立的参考换算开口，公开 `opening_valid、calibration_id、opening_method`。断电、齿轮重装、打滑检测或参考失效后，先失效该换算；界面显示未知，不能继续拿旧 J7 零位推算毫米。重新标定是一项可能运动的显式操作，不在加载页面时自动执行。

位置有效性与范围告警分开：`q_valid` 表示该角度是否有新鲜可信反馈，`within_operating_range` 表示是否位于已批准范围。越界但有效的反馈按原值显示并告警，不能夹成边界值；缺电流不能让位置一起失效。遥测另附 sample time 与 stale 状态。

**验收：**保留已有 3 组 end_link 数学对照；增加工作位、J2/J3 停放位、最大开口、失效夹爪参考、无电流、有角度六类样例。实机 TCP 和相机外参的误差验收由 D2 的测量预算决定，不用浮点计算误差替代标定精度。

## 5. D2：测量口径的解决办法

### 5.1 装配检查采用径向偏差加落座检查

为工装建立坐标系 F：定位柱轴线为 Z，工装基准平面确定 XY。每次识别定位柱与工装后，保存 `fixture_pose、frame_id、captured_at、calibration_id`；不能依靠物体在图像中的固定位置。

| 指标 | 定义 | 用途 |
|---|---|---|
| radial_mm | 零件装配孔中心相对柱轴的 XY 距离 | 判断是否对中 |
| seat_error_mm | 实测落座高度与配方目标高度之差的绝对值 | 判断是否落座 |
| deviation_mm | 本套零件 radial_mm 的最大值 | 对接首页“偏差 x.x mm” |
| valid | 所需零件与测量是否完整有效 | 区分没测到与不合格 |
| verdict | pass / fail / unknown | 最终检查结论 |

检查必须同时确认零件存在、顺序正确、径向合格和落座合格。下层零件被遮挡时，采用每次放置后的观察证据加最终检查；必须能证明工装位置未变、后续操作没有使前次结果失效。证据不足则 unknown，不能只看到最上层就判整套到位。

每个配方定义 `radial_tolerance_mm、seat_tolerance_mm`，从孔柱间隙、层高或实测合格样件取得，不沿用模拟数据的 1 mm。公差未配置时拒绝进入可判定合格的生产模式，报 `inspection_profile_missing`。

测量系统以独立量具或已知尺寸样件核对，给出验证范围内的误差上界 U。合格判据为 `radial_mm + U_xy ≤ radial_tolerance_mm` 且 `seat_error_mm + U_z ≤ seat_tolerance_mm`。测量区间与公差边界重叠时判 unknown；明显超出时判 fail。不能因为画面显示一位小数，就宣称具有 0.1 mm 精度。

画面上“到位”只对应 verdict=pass。fail 显示具体的径向或落座原因，unknown 显示“无法确认”及原因。`deviation_mm:null` 不画成 0；抓取阶段的 `tip_error_mm` 保留为运动到位诊断，不能拿来充当装配偏差。

### 5.2 识别置信度使用独立样本校准

后端原有 distance、margin 保留为原始评分。用按采集批次隔离的带标注样本训练正确率校准器，估计 `P(当前类别正确 | distance, margin)`；另留一批样本验证，保存 calibration_id、样本数和可靠性结果。原始分数不能直接改名为概率。

有有效校准器时返回 confidence 0–1；未校准、类别未覆盖或输入超出验证范围时为 null，并标明 confidence_status。前端不显示虚构百分比，可显示已识别名称和“置信度未校准”。是否允许该类别进入生产由后端拒识规则和工件验收结果决定，不能仅靠一个显示分数放行。

识别框从真实轮廓取得，附图像宽高与 frame_id；取点、画框、深度、关节姿态必须关联同一拍摄时刻。夹爪闭合方向使用 grasp_plan 的方向，不混用物体长轴方向。

### 5.3 夹持力、试抓和训练偏差各有来源

| 数据 | 处理办法 |
|---|---|
| 文档 force_n | 定义为每指法向力；带 source=measured/estimated/unknown |
| 估算力 | 保留质量、摩擦系数、安全系数与双指公式，标明仅是估算 |
| 真实执行 | 继续使用已批准的 grip_torque_nm；不把 12 N 当作 12 N·m |
| 力矩换算力 | 有夹具传动与力传感标定后才启用，保存换算版本和适用范围 |
| grasp_ok | 来自夹持与抬升复核，不能用“命令没报错”代替 |
| 零件训练偏差 | 实际夹取参考点与目标夹取参考点的位移差，说明坐标与测量方式 |
| 配方训练偏差 | 使用与生产相同的径向和落座指标，不复用抓取到位误差 |

生产记录中的一次通过率按“首次检查明确通过套数 / 已执行首次检查套数”计算，fail 与 unknown 都不算通过；检查前取消、急停或执行失败单列，不进入该分母。每个 run_id 只计一次，复检不能把失败改算首次通过。额外记录执行失败数，避免统计掩盖中途失败。

训练用真实轮次数据，允许曲线上升；无外部测量就返回 null 并注明原因。训练结束由版本化策略决定，包含目标、验证集、停止条件和超时，不能固定跑 8 轮就声称达标。达到软件终止条件与通过工件验收是两个状态。

**验收：**包含合格、已知偏移、未落座、缺件、顺序错误、深度缺失、遮挡、标定过期和置信度未校准。验证集必须含公差边界两侧样本，误差不足以区分时输出 unknown，不放宽公差迁就测量。

## 6. D3：接口不一致的解决办法

在主机增加独立的控制台协议适配层，复用一份 Panel 和一套设备工作线程；前端新增真机数据源。保留旧 `/api/state`、`/api/cmd` 作为旧面板接口，不让页面直接拼旧 action。

| 当前后端 | 适配后的 v2 数据 |
|---|---|
| telemetry.q_rad/dq_rad_s | 六轴 joint_state，J7 转夹爪字段 |
| tau_nm、两种温度 | 带单位与独立有效性的遥测 |
| connected/enabled/stale | 连接、驱动与数据新鲜度，分别表达 |
| vision.last | 关联图像帧的识别结果 |
| last_pick | 当前抓取结果，按 task/step 关联 |
| server_time | Unix 秒转 Unix 毫秒 |
| HTTP ok/detail | 接受结果或旧动作结果，不直接当生产成功 |

旧状态缺少的 phase、run_id、失败原因、训练和检查结果，由业务编排产生；不能从中文日志猜测，也不能靠轮询间隔拼出已经丢失的短阶段。

具体要求：

- 普通命令异步接受，立即返回 request_id 和任务 ID；长动作结果通过事件与查询返回，不占住请求等待 120 秒。
- request_id 重复且载荷一致时返回原结果，不再执行；同 ID 不同载荷拒绝。主机重启后仍能查询已落盘请求；未明确完成的业务任务结束为 status=failed、code=interrupted，物理结果另记 outcome=unknown，不自动续跑。查询不到的请求返回 request_not_found，不推断动作未发生。
- 首连先 hello，再发送同一水位的快照，之后顺序发送更晚事件。前端丢弃重复序号，同 session 的缺口触发重新取快照。
- 假设 TCP/WS 连接仍活着不代表机械臂有新数据；分别检查控制连接、遥测、相机新鲜度。断线不自动切回模拟。
- 同源提供控制台、API 与媒体。调试跨源只允许指定 Origin；令牌通过实际认证机制传递，不放访问链接里。旧调试入口同样受主机控制权和忙碌锁约束。

媒体文件使用可访问的资源 ID/URL；不能给浏览器本机路径。生产与训练记录由主机持久化，库更新带 revision，分页查询有稳定游标。

**验收：**使用假 Panel 跑 HTTP/WS 集成；覆盖连接、坏 JSON、未知能力、双击、重复请求、慢命令、快照竞态、断线、事件缺口和重启。整个测试不打开真实串口或相机。

## 7. D4：急停与恢复的解决办法

保留驱动已定义的紧急下使能路径；协议层增加停止锁存和任务取消，不把急停改成等待归位。停止效果如实上报，不能宣称断电后姿态不动。

| 操作 | 明确定义 | 禁止的隐式动作 |
|---|---|---|
| estop | 立即触发独立停止路径，失效本轮取消令牌 | 不等待普通队列，不先回位 |
| reset_estop | 检查恢复前提后解除软件锁存 | 不使能、不运动、不清历史、不续跑 |
| arm_enable | 人工确认后使能保持，必须走不带归位的显式动作 | 不复用会自动回位的 enable 包装 |
| return_home | 独立确认、规划和监控的归位任务 | 不由页面加载、重连或清记录触发 |
| reset_demo | 只给模拟提供快捷重置 | 真机返回 unsupported，不触发运动 |

真机若需要清本次显示统计，新增 `clear_session_stats`，保留持久化审计和生产历史。前端模拟“一键重置”保持原行为；连接真机后改为明确的解除、使能、归位步骤，不能一个按钮连续调用三个动作。

停止状态使用 `stop_requested、drive_feedback、motion_state` 分开表达。发送成功不等于停止确认；失去反馈则 motion_state=unknown。当前旧接口即使下使能异常也可能返回 ok:true，适配层必须取得结构化错误和设备反馈，不能解析一个成功标记就报“已停稳”。

取消令牌在每个动作开始前、动作内部可中断点和结束后检查。急停后队列中该 run/train 的动作全部作废；解除后也不恢复。普通任务只能有一个设备所有者，旧面板、训练、生产、标定不能绕开互斥。

失联处理分开：设备通信故障继续遵循已有驱动保护；浏览器控制链路丢失时停止安排后续工序，调用已验证的受控停止能力。若现有驱动不能在持物中安全受控停止，该能力必须标 unavailable，不能在代码里自动选择“继续跑完”或“直接松爪”。现场负责人先确定支撑、防坠与恢复流程，持物生产验收在此之前不放行。

**验收：**假驱动覆盖急停插队、停止失败、反馈缺失、残留队列、解除不移动、使能不归位、归位需单独请求。真机按空载到有支撑工件逐级验收并记录停止效果；没有实测结果不得标完成。

## 8. D5：补齐完整装配流程

新增主机侧 RunService，接 `run_start {recipe_id, recipe_version}`。状态由动作结果驱动，不能用前端时间线驱动机械臂。

| 工序 | 复用 | 必须补齐 |
|---|---|---|
| 自检 | 驱动连接、遥测、相机状态 | 9 项结构化结果及版本、标定、配方前提 |
| 到观察位 | 已录轨迹和回放能力 | 确认轨迹 ID、版本、相机观察条件 |
| 识别 | 现有零件识别和 grasp_plan | 工装/柱检测、物体实例、目标匹配 |
| 抓取 | 当前 pick 的规划和保护 | 可复用分阶段动作，返回结构化结果 |
| 放置 | 现有运动基础能力 | 目标柱坐标、放置姿态、接近与撤离策略 |
| 检查 | 相机与深度 | D2 定义的径向、落座、存在性及顺序判断 |
| 收回 | 初始姿态与轨迹 | 无持物、路径有效、驱动正常的回位前提 |

把当前 `_cmd_pick` 拆出可复用的抓取阶段，旧 pick 对外行为保持“抓起放回”。新编排调用 `pick_target`、`place_target` 等内部动作，不用 `place_back:false` 冒充完整装配。每段动作输出 started/completed/failed 事件及测量依据，不用长中文字符串当机器接口。

配方步骤保存 part_id、fixture_id、assembly_target_id、装配顺序、目标关系、有效版本和公差。assembly_target_id 表示工装上的装配位置，识别 target_id 表示本轮检测到的零件实例，两者不得混用。工装可移动，目标从本轮识别的工装坐标转换；固定轨迹仅用于经验证的观察与收回阶段。现有只检查连杆原点高度的预检不等于完整碰撞检查，放置路径还需覆盖夹爪、工件和工装空间。

夹持确认失败时停止本轮，不继续放置；放置或检查失败时保留结果，是否允许撤离由当前持物状态与已验证路径决定。不能在异常处理的 finally 里无条件松爪或回折叠位。

检查完成后发唯一 `run_result`，包含 verdict、各项测量和计数依据；收回完成再发 `run_finished`。若收回失败，已获得的装配结果保留，但整项操作为 failed，开始按钮保持不可用。只有明确的 ready 状态才接受下一套。

零件库使用 D1/D2 的真实字段，配方与模型版本在运行开始时固定。新零件或配方训练以异步 TrainService 对接现有算法；完整事件为进度、成功文档更新或失败，任务互斥与取消复用 D4。没有实际训练能力时不声明相应 capability。

**验收：**假设备先跑两次抓放的完整配方，并注入漏检、抓空、卡住、放置失败、检查无效、急停与收回失败；确认每种失败都停止后续动作且不伪记成功。再安排逐段真机验证，不直接一次跑完整套。

## 9. D6：交付与验收

新增验收入口分别在前端和主机仓库运行，默认使用假设备，真实模式必须由现场明确选择。输出包括双方提交号、profile/calibration/model 版本、用例结果、JSON 事件记录和界面截图。

| 验收组 | 通过标准 |
|---|---|
| 设备参数 | 同一 profile 下角度、夹爪、单位与末端点一致，缺测不补零 |
| 测量 | 已知样件与误差预算符合配置公差，不确定结果不判通过 |
| 协议 | 双方同样例一致，去重、快照和重启恢复无重复动作 |
| 安全流程 | 急停可插队，恢复不隐式运动，断线行为按实测方案执行 |
| 生产 | 两件装配、检查、收回闭环；每个失败用例有明确终态 |
| 兼容 | 旧训练 v1、旧面板和节点①模拟用例继续通过 |

必须交付的实际待办：设备负责人给出当前夹具 TCP/相机标定与有效夹爪参考；工艺负责人给出孔柱与落座公差及合格样件；现场负责人确认失能支撑、防坠和恢复流程。人员姓名未定，按职责指派，不冒写已确认。

回滚以每个工单的独立提交为单位。新协议入口可停用，旧服务可继续使用；设备配置和标定保存带版本副本，不能靠回退前端代码恢复硬件参数。已产生的记录和用户数据不得因回滚删除。
