# 换机械臂模型：总体设计（Claude 定，Codex 照做）

本文件是各个任务共用的依据。每个任务的说明只写“这一步做什么”，结构和命名以这里为准。

## 1. 旧页面怎么保住：认领机制

旧的 3 关节打靶面板（`app.js` + Python 仿真后端）整体保留，不拆、不重写。新内容由一个可选模块 `modules/trainer/` 接管首页上的若干区域。

- `app.js` 只加一个接缝：`const claimed = region => (document.documentElement.dataset.claim || "").split(" ").includes(region)`。`render()`、`refreshCamera()` 等在写某个区域前先看它有没有被认领，被认领就跳过。除此之外 `app.js` 不认识 trainer。
- 区域名固定为：`kpis`（四个数据格）、`joints`（关节卡片）、`feed`（最近事件）、`errchart`（误差曲线卡片，含标题和图例）、`diag`（诊断候选卡片，含标题）、`cam`（摄像头画面、叠加层和画面上的芯片）、`actions`（顶栏的“自检”和“⋯”菜单）。
- 没被认领的保持原样、仍由 `app.js` 渲染：学习效果卡片、版本下拉、数据总览页、故障码页、急停按钮和急停横幅、断线横幅。
- `modules/main.js` 加载 trainer：地址栏带 `?legacy=1` 时不加载。trainer 加载失败或被删除时，页面自动就是旧版。`index.html` 的静态结构不改（只允许加挂载位），所以旧测试不用改。
- trainer 启动时先 `document.documentElement.dataset.claim = "kpis joints feed errchart diag cam actions"`，再往这些区域里写自己的内容（改标题文字、换内容，不改卡片位置和栅格）。
- 解说条模块 `modules/guide/` 讲的是旧的自愈流程：非 legacy 时不加载它。
- 急停：旧的急停按钮和行为不动。trainer 另外监听急停按钮的点击，向自己的数据源补发 `estop` 和 `laser_off`；另一台主机回报急停时，trainer 在自己的区域里显示，不改旧的急停横幅逻辑。

## 2. 机械臂参数只在一处：`modules/arm/`

| 文件 | 职责 |
|---|---|
| `modules/arm/arm-params.js` | 唯一的参数来源：6 个关节（id、中文名、URDF 原点、转轴、限位）、`end_link` 固定变换、夹爪（开口范围、两根夹指的安装变换）、`T_end_tcp`、`T_end_camera`、`T_end_laser`、相机外形与视场角、显示用的安装台高度、旧 3 轴映射（`legacyPanelMapping`、`legacyRestPose`，只给旧数据源用）。每个估算值旁边注明来源（URDF / 照片估算 / 占位）。 |
| `modules/arm/fk.js` | 纯函数，不依赖 DOM 和 three.js。见下。 |
| `modules/arm/trajectory.js` | 纯函数：把按时间排列的原始关节帧算成末端路径。 |

`modules/twin/arm-config.js` 改成从 `arm-params.js` 转出同名对象（保持现有导入不断）；`modules/twin/kinematics.js` 保留，`forward()` 的返回值里把 `tool` 改名为 `end_link`，同时保留 `tool` 作为同值别名一个版本，避免旧代码断。

### fk.js 接口

```js
checkJoints(params, q)          // q: 长度 6 的 rad 数组。返回 { ok, issues: [{ joint, kind: "missing"|"nan"|"out_of_range", value }] }。不修改输入，不夹限位。
forwardUrdf(params, q)          // 6 轴 URDF 角 → { frames: {joint1..joint6: 4×4}, end_link: 4×4 }。输入必须先过 checkJoints；这里不夹限位、不补 0。
endPoses(params, q)             // → { end_link, tcp, camera, laser }，后三个 = end_link · T_end_*（右乘）
laserRay(params, q)             // → { origin:[x,y,z], direction:[x,y,z] }（基座系，m）
```

矩阵沿用 `kinematics.js` 的约定：长度 16、行主序、平移在 3/7/11，长度单位 m，角度 rad，坐标系是 URDF 的 `base_link`（Z 向上）。0.2 m 安装台只在 `scene.js` 里画，不进任何换算。

### trajectory.js 接口

```js
buildPath(params, samples, { point = "tcp", maxGapMs = 500 })
// samples: [{ t, q:[6], valid?:[6] }]（t 为 Unix 毫秒）。逐帧用原始 q 算末端。
// 返回 { segments: [[{ t, p:[x,y,z] }...], ...], dropped: [{ t, reason }] }
// 帧无效（缺轴、NaN、越界、valid 里有 false）或与上一帧间隔超过 maxGapMs 时断开成新的一段，不补点。
```

## 3. JointFrame（数据源 → 显示模块）

```js
{
  timestamp,          // Unix 秒
  q_rad,              // 长度 6 的 URDF 角（rad），或 null。新数据源用这个
  valid,              // 长度 6 的布尔数组，缺省视为全 true
  gripper_mm,         // 夹爪开口（两指内侧间距，mm），或 null
  angles_deg,         // 旧的 3 轴面板角度（度），只有旧数据源（panel / sim / device）会给
  mode, online, laser // 含义不变
}
```

孪生收到 `q_rad` 就直接走 6 轴入口（`forwardUrdf`）；只有 `angles_deg` 时走旧的 3 轴映射。动画平滑只影响画面，不外传。孪生的关节标签在 6 轴入口下显示 J1–J6。

## 4. 孪生新增的显示（另走事件，不混进 JointFrame）

`twin.setOverlay(overlay)`，由 trainer 通过 `modules/main.js` 接线；`overlay` 的字段都可缺省：

```js
{
  demoPath:   segments,          // 示范末端路径（虚影）
  runPath:    segments,          // 这一遍的末端路径
  nodes:      [{ id, p:[x,y,z], current:boolean }],
  laser:      { on:boolean },
  spots:      { measured:[x,y,z]|null, reference:[x,y,z]|null, deviation_mm:number|null }, // 基座系，m
}
```

孪生自己根据当前姿态用 `endPoses` 画相机（机身 + 视锥）、激光头；激光开时沿 `laserRay` 画光束。夹爪：两根夹指按 `gripper_mm` 沿滑轨对称平移。

## 5. 面板 ↔ 另一台主机（接口 v1，详见 `docs/接口文档.md`）

- 推送：WebSocket，每条 `{ v:1, type, seq, t, ... }`，`t` 一律是 Unix 毫秒（主机时钟）。类型：`hello`、`joint_state`、`laser_state`、`demo_trajectory`、`node_result`、`pass_result`、`correction`、`event`、`heartbeat`、`error`。
- 指令：HTTP `POST {base}/api/v1/command`，体 `{ v:1, cmd, seq, t, ...参数 }`，应答 `{ v:1, ok, code, msg, seq }`。`cmd`：`demo_start`、`demo_stop`、`practice_start`、`practice_stop`、`estop`、`reset_estop`、`mark_node`（预留）、`laser_on {ttl_ms}`、`laser_renew {ttl_ms}`、`laser_off`。
- 地址：`?backend=ws://主机:端口/路径`。HTTP 基址由它推出（`ws`→`http`、`wss`→`https`，同主机同端口）。没有这个参数才用浏览器内的模拟主机；给了参数连不上就显示离线，不回退。
- 数据源层新增 `modules/datasource/host-source.js`（真主机）和 `modules/datasource/mock-host.js`（模拟主机，实现同一套消息和指令）。两者对外接口相同：`{ kind, start(), stop(), subscribe(cb), send(cmd, args) → Promise<应答> }`，`subscribe` 的回调收到的是接口文档里的原始消息对象，外加连接状态消息 `{ type:"link", online:boolean }`。

## 6. trainer 模块结构（`modules/trainer/`）

| 文件 | 职责 |
|---|---|
| `store.js` | 纯函数：`reduce(state, message)`，把消息累积成页面状态（模式、最新关节帧、示范轨迹、每一遍结果、修正记录、激光状态、事件、连接状态）。 |
| `metrics.js` | 纯函数：第几遍、最近一遍偏差、比第一遍好了多少（%）、修正次数等。 |
| `laser-guard.js` | 激光的全部规则：到节点停稳自动开、收到结果或超时自动关、开着就续期、手动开关、急停 / 断线 / 切页面 / 关页面立即关。依赖注入时钟和 `send`，可在 Node 里测。 |
| `views/*.js` | 每个被认领的区域一个文件：`kpis.js`、`joints.js`、`feed.js`、`deviation-chart.js`、`corrections.js`、`camera.js`、`controls.js`。每个只管自己的区域。 |
| `trainer.js` | 认领区域、创建数据源、把 store 的变化分发给各个 view 和孪生。 |
| `trainer.css` | 只放 trainer 自己新增元素的样式，颜色字号只用 tokens。 |

可配置项集中在 `modules/trainer/config.js`：偏差阈值 5 mm、激光有效时长 3000 ms、续期间隔 1000 ms、节点等待超时 2000 ms。

## 7. 不许做的事

- 不删、不改 `rearm/` 下的 Python 算法、`config/`、急停与限位的行为。
- `app.js` 除认领接缝外不加别的东西；`app.css` 不加新样式。
- 前端不写死任何真机地址。测试和开发期间激光指令只发给模拟数据源。
- 不 push，不合并到 main，不改写历史，不删分支，不往项目 `.venv` 装包。
