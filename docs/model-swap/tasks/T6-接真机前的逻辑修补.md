差异表里以下五条要改成和设计一致（其余保持现状，只在文档里留着）：

1. **D01 激光不一致告警不能跨时钟比较。** 判断“面板期望与主机回报不一致超过 1 s”时，两个时间都用面板本地时钟：面板发指令的本地时刻，和面板**收到** `laser_state` 的本地时刻（store 收到消息时记一个 `received_at`，由调用方传入本地时钟，store 保持纯函数）。主机消息里的 `t` 不参与这个判断。
2. **D04 激光时长以主机 `hello` 为准。** `laser-guard` 收到 `hello` 后，`laser_ttl_ms`、`node_timeout_ms` 有合法正数值就覆盖本地默认值（3000 / 2000）；续期间隔取 `min(1000, ttl/3)`。没收到或值不合法就用默认值。
3. **D05 静默超时要主动重连。** `host-source` 超过 `offlineAfterMs` 没收到任何消息时，除了发 `{type:"link", online:false}`，还要关掉当前 WebSocket 并按 `retryMs` 重连（避免卡在一条半死的连接上）。重连成功后照常发 `online:true`。
4. **D07 无效测量不能继续显示旧光点。** 当前节点最新的 `node_result` 为 `valid:false` 时：孪生的 `spots` 清空；手眼相机画面上不画光点和箭头，改在画面中央下方显示“未找到光点”（或按 `invalid_reason` 显示：`spot_not_found`→“未找到光点”，`depth_invalid`→“深度无效”，`timeout`→“测量超时”，其它→“测量无效”）；进入下一个节点后清除这条提示。
5. **D10 达标口径统一。** 数据格②的“低于阈值 / 高于阈值”改为按 `pass_result.below_threshold` 判断（主机按最大偏差和全部节点有效来判）；没有该字段时按“最大偏差 ≤ 阈值且全部节点有效”在面板算。文字改为“✓ 达标（最大 ≤ 5 mm）”/“▲ 未达标（最大 6.9 mm）”，主数字仍显示平均偏差。

每条都加测试（Node 跑纯函数或用假的 WebSocket / 假时钟）。改完后更新 `docs/接口文档.md`：第 12 节差异表里这五条改成“已按设计实现”并简述做法，第 7、10 节相应描述同步；修订记录加一行。
