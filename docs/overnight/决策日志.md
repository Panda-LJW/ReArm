## D2 数字孪生按哪台臂建模

- 问题：建模参考目录核实的实物是 **Seeed reBot Arm B601-DM**（6 轴 + 夹爪，大臂 264 mm、小臂约 249 mm，24 V 达妙电机）；而上位机代码里的自我模型是一台 **3 自由度小臂**（肩高 85、大臂 150、小臂 130 mm，7.4 V 舵机）。两者不是同一台机器。
- 选择：孪生按 **B601-DM 的官方 URDF 参数**建模（连杆原点、转轴、限位原样取自 `ReBot_Arm_DM.urdf`）；上位机现在给出的 J1–J3 三个读数驱动它的前三个关节，J4–J6 固定在一个静止姿态。
- 为什么：任务要求“按实际关节参数建模”并先读建模参考；参考目录里能确认的实物就是 B601-DM。
- 备选：按上位机配置的 150/130 mm 小臂建模（和仿真数据自洽，但不是实物）。
- 影响与改回：所有几何和映射集中在 `rearm/ui/static/modules/twin/arm-config.js`，换臂只改这个文件。
- **待你决定**：上位机的名义参数（`config/arm_nominal.yaml`）是否要改成 B601-DM 的尺寸。这会影响仿真、标定和报告，属于核心逻辑，我没有动。

## D4 为什么模型站在一个台子上

- 问题：仿真数据是给小臂算的姿态，套到更长的 B601-DM 上，部分姿态末端会低于底座平面（例如 J2 = 40°、J3 = −100° 时低 132 mm），画出来像穿地。
- 选择：把臂画在 0.20 m 高的安装台上，地面网格在台子底部。
- 为什么：不改数据、不造假姿态，只改画面布置；真机若装在桌沿也是这个样子。
- 改回方式：`arm-config.js` 的 `scene.pedestalHeight` 改成实际值。

## D6 模型放在哪

- 选择：首页右栏里，**关节、最近事件靠左各占一半宽，模型占右半并上下贯通**。矮屏（高度 ≤ 800）时最近事件本来就收进下方卡片，模型与关节并排。
- 为什么：
  1. 视线从左到右是“靶面画面 → 数字读数 → 机械臂本体”，两块图像分居两端，中间是文字，画面平衡。
  2. 关节读数条紧挨着模型，观众能直接对上“J2 +55°”和模型上的 J2 标签。
  3. 模型需要接近方形的区域，纵向贯通两块比横向切一条更合适。
- 备选：模型放在摄像头和数据之间（会把四个数据格挤窄）；放在页面下排（下排三张图已满）。
- 改回方式：`modules/main.css` 里的 `grid-template-areas`。

## D7 模块之间怎么通信

- `app.js` 只多了三行：每次渲染后广播 `rearm:state` 事件（带当前状态和连接情况），并监听 `rearm:theme`（主题变了就重画图表）、`rearm:modules-ready`（模块就绪后补发一次状态）。它不引用任何模块文件。
- 数据源层（`modules/datasource/`）把各种来源整理成同一种 `JointFrame`：`{ timestamp, angles_deg, mode, online, laser }`。
- 孪生（`modules/twin/`）只有 `createTwin(el)` → `update(frame)`，不认识数据源，不读页面其它元素。
- 装配只在 `modules/main.js` 一处。任何模块加载失败只影响自己，页面其余部分照常。
- 换数据源：地址栏 `?twin=sim`（内置模拟）、`?twin=device&device=ws://…`（下位机）、`?twin=off`（关闭孪生）。缺省用面板数据。

- 字号：最小 18px；屏高超过约 970px 后按 1.85vh 继续放大（1080p 下约 20px），四个数据格的数字 1080p 约 71px、720p 约 48px。

## D11 下位机通信方式的推荐

- 问题：通信方式尚未确定，文档主体要按一个推荐方案写。
- 选择：**USB 串口（CDC 虚拟串口），每帧一行 JSON 文本 + `*` + CRC16 + 换行**。同一份 JSON 也能原样跑在 TCP / WebSocket 上（去掉 CRC 后缀）。
- 为什么：
  1. 路演现场排查最省事：任何串口工具都能直接看懂报文。
  2. `requirements.txt` 里已有 `pyserial`，上位机接入成本最低。
  3. 上位机验完 CRC 后可把同一份 JSON 转发给浏览器，前端 `device-source.js` 已按这个结构解析。
  4. 字段可以按版本追加，不用改帧布局。
- 代价：比二进制帧占带宽（6 轴全字段一帧约 647 字节，50 Hz 约 32 kB/s，占 921600 bps 串口的三成多）。资源紧张时的二进制布局放在文档附录 C。
- 备选：CAN 直连（不设下位机，上位机经 USB-CAN 直接驱动达妙电机）。这条路固件工作量最小，但保护逻辑全在上位机，安全上更弱，文档里列了对比，没有作为主体。
- **待你决定**：是否接受这个推荐；下位机用什么主控（影响 CDC 是否可用）。
- 文档由 Codex 起草、我逐节验收，一次通过，未打回。我改了一处：前端解析遥测时遇到缺测（`null`）、缺轴、重复 id 现在整帧作废，不再把 `null` 当成 0，并同步改了文档里的对应描述。

## D12 模型外形：在简化外形之上加了一套真实外形

- 问题：用方块和圆柱拼的简化外形能说明姿态，但路演上不够“像真的”。
- 选择：把建模资料包里 rebot-joycon 的官方 B601-DM 网格（43 万三角面、约 21 MB）用顶点聚类压到 **6.5 万面、1.1 MB**，存为 `modules/twin/meshes/b601.{json,bin}`，孪生启动后后台加载，成功就换上；加载失败、文件被删或没有 WebGL 时自动保持简化外形。运动学不变，仍只看 `arm-config.js`。
- 为什么：观感提升很大；文件小，不影响加载；失败有退路，符合“稳定可演示”。
- 与实物的差异：官方是尖头夹指，实物照片是白色矩形镂空夹指（没有 CAD）；配色按面板主题做了中性处理，没有用官方的黄色。
- **待你决定（许可证）**：这套网格源自 Seeed 的 CERN-OHL-W-2.0 开源硬件设计。仓库里附了来源和修改说明（`meshes/NOTICE.md`）。仓库只在本地、不对外分发时没有问题；如果要公开仓库或随产品分发，需要你确认是否接受该许可证。不接受就删掉 `modules/twin/meshes/` 目录，孪生自动退回简化外形。
- 重新生成：`.venv/bin/python scripts/build_twin_meshes.py <资料包.zip> --cell-mm 2.5`（数值越小越精细、文件越大）。
- 只看简化外形：地址栏加 `?skin=simple`。
