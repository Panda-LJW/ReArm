# 视觉参考：工业控制界面的可借鉴手法

目的：给 `feat/panel-visual` 分支的视觉升级定方向。目标是工业科技感、克制、高级；禁用霓虹渐变、紫蓝渐变、滥用发光和模板味。

说明：下面五个案例里，标了“查证”的内容是这次联网搜索到并读过来源的；标了“通识”的是行业里广为人知、但这次没有逐条核对原文的做法。链接放在每节末尾。

## 1. ISA-101 高性能 HMI（流程工业的画面规范）

- 查证：平时的画面用灰阶，颜色只留给异常和报警；设备故障时不给设备本身上色，而是在旁边放一个带颜色、形状和文字的报警标记；每个报警级别有自己的形状、颜色和编号；颜色必须配文字，照顾色觉差异；用小型趋势线、模拟量指示条让人一眼看出“在不在正常范围”。
- 借鉴：
  1. **正常时安静，异常时才有颜色**。面板现在的蓝色用得偏多（标题条、按钮、曲线、关节标记、标签）。升级时把蓝色收到“当前选中 / 可操作”两处，数据本身用中性的浅色。
  2. 报警用“形状 + 颜色 + 文字”，这和 P1 做的三重编码是一回事，视觉分支沿用。
  3. 关节读数条已经是“模拟量指示条”，可以再加一段表示安全范围的底色带。

来源：[Inductive Automation：High Performance HMI Techniques](https://docs.inductiveautomation.com/docs/7.9/visualization-and-dashboards/understanding-components/high-performance-hmi-techniques.md)、[Control.com：Going Gray](https://control.com/technical-articles/going-gray/)、[ISA Interchange：The High Performance HMI](https://blog.isa.org/the-high-performance-hmi)

## 2. Astro UXDS（美国太空军地面系统的开源设计规范）

- 查证：深色主题是默认；状态色固定六种——严重（红 #ff3838）、重要（橙 #ffb302）、注意（黄 #fce83a）、正常（绿 #56f000）、待命（蓝 #2dccff）、关闭（灰 #a4abb6），在深色背景上都满足 WCAG AA 对比度；红色只留给需要立刻处理的状态；规范明确反对自己再加状态色，因为会增加学习成本。
- 通识：它的每个状态除了颜色还有固定的形状（不同状态用不同的几何图形）。
- 借鉴：
  1. **状态色数量固定、含义唯一**。面板现有四种语义色（青＝正常、琥珀＝进行中、红＝异常、蓝＝信息），够用，不再增加；升级时保证同一种颜色不兼做装饰。
  2. 顶部一条全局状态栏，永远在同一位置回答“现在整体怎么样”。面板的顶栏可以承担这个角色。

来源：[Astro UXDS：Status System](https://astrouxds.com/patterns/status-system/)、[Astro UXDS：Status Symbol](https://astrouxds.com/components/status-symbol)、[Astro UXDS：Compliance](https://www.astrouxds.com/design-guidelines/compliance/)

## 3. NASA Open MCT（开源的任务控制数据显示框架）

- 查证：由 NASA Ames 开发并开源（Apache 2.0），用于多个 JPL 任务的遥测显示；显示页面由可组合的对象拼成，每块只管一类数据；同一套界面要在控制中心大屏和移动设备上都能看。
- 通识：界面极其朴素——深色底、细线分隔、等宽数字、几乎没有装饰，图表的网格线很淡，数据线是画面里最亮的东西。
- 借鉴：
  1. **数据是画面里最亮的东西**，容器（卡片边框、标题条、网格线）尽量退后。升级时降低卡片标题条和边框的存在感，提高数据曲线和数字的对比。
  2. 数字全部等宽、右对齐、带单位，单位比数字小一号且颜色更淡。面板已基本做到，升级时统一检查。

来源：[About Open MCT](https://nasa.github.io/openmct/about-open-mct)、[NASA Spinoff 关于 Open MCT 的介绍](https://spinoff.nasa.gov/node/11075)

## 4. SpaceX 载人龙飞船的座舱显示

- 查证：三块大触摸屏是航天员的主要界面；设计思路是先找出关键功能，再拆成一屏只做一件事、容易消化的画面；屏幕只显示当前阶段需要的控制项；最关键的操作在屏幕下方保留了实体按键作为备份。
- 通识：画面是近乎纯黑的底色，细的浅色线条和文字，颜色极少，只有少量蓝色表示可操作、少量橙红表示警告；大量留白；中央是一个三维的飞船姿态图，周围是数字读数。
- 借鉴：
  1. **近黑底 + 细线 + 极少的颜色** 就是“克制的科技感”，不需要渐变和发光。
  2. 中央三维姿态图配周边读数，和我们“数字孪生 + 关节读数”的组合一致；孪生可以用线框感更强的渲染（浅色描边、暗色面），而不是塑料感的实体着色。
  3. 急停这类关键操作要有固定位置、与其它按钮明显不同，面板已做到。

来源：[Space.com：Crew Dragon 触摸屏操作](https://www.space.com/spacex-crew-dragon-touchscreen-astronaut-thoughts.html)、[Hackaday：Dragon 的 HTML 界面](https://hackaday.com/2020/06/08/displaying-html-interfaces-and-managing-network-nodes-in-space)

## 5. F1 遥测与转播图形

- 查证：赛道墙的决策依赖几十毫秒内的新数据；一辆车有三百多个传感器通道，画面要同时放很多条曲线；可视化不能为了流畅把短暂的尖峰抽样掉，否则关键事件会消失。
- 通识：转播图形的特点是大号的等宽数字、紧凑的大写标签、很细的分隔线、每支车队一个固定颜色；计时榜上用紫／绿／黄三色表示“全场最快／个人最快／更慢”，颜色含义全场统一。
- 借鉴：
  1. **大数字 + 小标签** 的层级：标签小而紧凑，数字大而等宽。路演模式的四个数据格已经这么做，日常模式也可以加大数字与标签的反差。
  2. 误差曲线不要平滑、不要抽样，尖峰就是我们要给观众看的“受伤瞬间”。现有实现是逐发画点，保持不变。
  3. 标签用略大的字距，让中文小标题也有“仪表”感。

来源：[SciChart：赛车遥测的实时可视化](https://www.scichart.com/blog/best-real-time-visualization-telemetry-sensors-motorsport/)、[Dronedesk：F1 遥测数据说明](https://blog.dronedesk.io/f-1-telemetry-data/)

## 归纳成本次升级的六条规则

1. **底色近黑、分层靠明度**：背景、卡片、标题条只差一两级明度，不用渐变。
2. **颜色只表达语义**：青＝正常，琥珀＝进行中，红＝异常，蓝＝可操作／当前选中。装饰一律用中性灰。
3. **数据最亮，容器最暗**：数字和曲线用最高对比；边框、网格线、标题条压低。
4. **细线和刻度代替色块**：用 1px 细线、角标、刻度营造仪表感，不用大面积色块和阴影。
5. **不发光、不模糊**：去掉外发光、毛玻璃；需要强调时用实色描边或加粗。
6. **数字等宽、单位小一号**：所有读数统一。

## 明确不做

- 渐变背景、霓虹描边、紫蓝配色、玻璃拟态、动态粒子或扫描线之类的装饰动画。
- 为了“好看”新增状态颜色，或把语义色拿去做装饰。
- 改布局和交互（那是产品方向的事，不在视觉升级范围内）。
